# PaperLab PC 앱 (Windows)

PaperLab 서재 화면과, **이 PC에 설치된 AI 도구(claude · codex · gemini)로 요약 · 대화 · 글쓰기 작업을 실행**하는 기능이 함께 들어 있는 Windows 앱입니다.
API 키가 없어도 PC의 AI 도구에 로그인되어 있으면 그 계정으로 작업을 쓸 수 있고, 앱이 꺼져 있는 PC는 작업을 받지 않습니다.

- Windows 10 · 11 (64비트)용입니다. macOS · Linux는 지원하지 않아요.
- 사용자가 아니라 개발자라면 맨 아래 [개발자용](#개발자용)으로 가세요.

## 1. 설치

1. 브라우저에서 PaperLab에 로그인합니다. (앱을 아직 설치하지 않았으니 브라우저로 먼저 들어가요.)
2. 설정 → **연결된 PC** → **[PC 앱 받기]** 를 누르고 **[설치 파일 받기]** 를 눌러요.
   "PC 앱을 준비 중이에요"라고 나오면 설치 파일이 아직 올라오지 않은 거예요. 관리자에게 알려 주세요.
3. 받은 `PaperLab-Setup-<버전>.exe`를 실행합니다.
4. **"Windows의 PC 보호" (SmartScreen) 창이 뜨는 것이 정상**이에요. PaperLab에는 코드 서명 인증서가 없어서 Windows가 처음 보는 프로그램으로 표시합니다.
   **[추가 정보]** 를 누르면 나타나는 **[실행]** 을 눌러 주세요. (**[추가 정보]** 를 누르기 전에는 [실행] 단추가 보이지 않아요.)
5. 관리자 권한 창 없이 설치되고(내 계정에만 설치), 바탕화면과 시작 메뉴에 `PaperLab` 바로가기가 생겨요.

### 받은 파일이 맞는지 확인하기 (SHA-256, 선택)

[PC 앱 받기] 창의 **"받은 파일 확인하기 (SHA-256)"** 에 파일의 지문이 있어요. PowerShell에서 아래 명령을 실행해 나온 `Hash` 값이 **그 지문과 같으면** 서버가 내보낸 파일 그대로예요(대문자 · 소문자는 달라도 같은 값).

```powershell
Get-FileHash "$env:USERPROFILE\Downloads\PaperLab-Setup-<버전>.exe"
```

지문이 다르면 실행하지 말고, 파일을 지운 뒤 다시 받아 주세요. 계속 다르면 관리자에게 알려 주세요.

## 2. 첫 실행과 로그인

1. 처음 실행하면 환영 화면이 나와요. **"Windows에 로그인하면 자동으로 시작"** 은 처음에 켜져 있어요(원하지 않으면 체크를 풀고). 서버를 확인한 뒤 **[시작]** 을 눌러요. 서버 주소를 입력하는 칸은 없어요(앱에 들어 있어요).
2. 로그인 화면에서 **[Google로 계속하기]** 를 누르면 **기본 브라우저가 열려서 거기서 Google 로그인**을 해요. (앱 창 안에서는 Google 로그인이 막혀 있어서 브라우저를 써요.)
3. 로그인을 마치면 브라우저가 "PaperLab 열기" 확인을 물어볼 수 있어요. 허용하면 앱 창으로 돌아와 서재가 보입니다. 앱 창에는 "브라우저에서 로그인을 마쳐 주세요" 안내가 보이고, [브라우저 다시 열기] · [취소]가 있어요.

## 3. 이 PC 연결 (AI 도구로 작업 실행하기)

앱을 설치하고 로그인만 해서는 이 PC가 작업을 받지 않아요. **이 PC를 연결**해야 해요.

- **앱 창에서 한 번에**: 설정 → **연결된 PC** → **[이 PC 연결]**.
- **코드로 연결**: 다른 기기(노트북 브라우저 등)에서 설정 → 연결된 PC → **[연결 코드 만들기]** 로 8자리 코드(예: `K7QF-2M9X`)를 받고, 이 PC의 **트레이 아이콘 → [코드로 연결…]** 에서 코드를 넣어 **[연결]** 을 눌러요. 코드는 10분 동안 한 번만 쓸 수 있어요.

연결되면 설정의 "연결된 PC" 목록에 이 PC가 **● 켜짐** 으로 보이고, 각 AI 도구의 상태(`claude ✓` · `! 로그인 필요` · `없음`)가 같이 보여요.
여러 PC가 켜져 있으면 **먼저 가져간 PC 한 대**가 작업을 실행해요. 작업은 **내 계정의 것만** 내 PC에서 실행돼요.

## 4. AI 도구(CLI) 준비

PC가 작업을 실행하려면 **claude · codex · gemini 중 쓰려는 도구를 이 PC에 설치하고 한 번 로그인**해 두어야 해요. 셋 다 필요하지는 않아요. 작업별로 어떤 도구를 쓸지는 설정 → **AI 엔진** 에서 골라요.

| 도구 | 설치 (명령 프롬프트 또는 PowerShell) | 로그인 |
|---|---|---|
| claude | `npm install -g @anthropic-ai/claude-code` (또는 Anthropic이 안내하는 Windows 설치 방법) | `claude`를 한 번 실행해 안내대로 로그인 |
| codex | `npm install -g @openai/codex` | `codex login` |
| gemini | `npm install -g @google/gemini-cli` | `gemini`를 한 번 실행해 Google 로그인 |

- `npm`이 없다는 메시지가 나오면 [Node.js](https://nodejs.org/) **LTS** 를 먼저 설치하세요. 각 도구의 설치 · 로그인 방법은 해당 회사의 공식 안내가 우선이에요(위는 대표적인 방법).
- **claude는 2.1.259 이상**이어야 해요. 낮으면 이 PC 상태에 **"! 업데이트 필요"** 가 보이고 claude 작업은 받지 않아요. 도구를 업데이트한 뒤 **[다시 확인]** 을 눌러 주세요.
- 설치 · 로그인을 마친 뒤에는 트레이 → **이 PC 상태** → **[다시 확인]** 을 눌러요. 상태 칩이 `✓ <버전> · 로그인됨`으로 바뀌면 준비 끝이에요. (앱은 30분마다도 다시 확인해요.)
- 도구를 설치했는데 **"설치되지 않음"** 으로 나오면 이 PC 상태의 **[경로 고르기…]** 로 실행 파일(`.exe` 또는 `.cmd`)을 직접 골라 주세요.
- 이 PC에서 쓰고 싶지 않은 도구는 이 PC 상태에서 체크를 풀면 그 도구의 작업은 받지 않아요. **동시** 칸에서 도구별 동시 실행 수(기본 claude 2 · codex 1 · gemini 1, 전체 2)를 바꿀 수 있어요.
- 앱은 API 키 환경 변수(`ANTHROPIC_API_KEY` · `OPENAI_API_KEY` · `GEMINI_API_KEY` 등)를 도구에 넘기지 않아요. PC에서는 **구독 로그인**으로만 실행돼요.

## 5. 트레이 · 자동 시작 · 업데이트

**트레이** (화면 오른쪽 아래 시계 근처, 숨겨진 아이콘 ^ 안에 있을 수 있어요)
- 앱 창의 **X를 눌러도 앱은 꺼지지 않고** 트레이로 숨어요. 작업도 계속 실행돼요. 처음 한 번 안내가 떠요.
- 아이콘을 누르면 PaperLab 창이 열려요. 오른쪽 클릭 메뉴: **PaperLab 열기 · 이 PC 상태 · 코드로 연결…(연결 전에만) · 작업 받기 일시 중지 · 업데이트 확인 · 로그 폴더 열기 · 종료**.
- **끄려면 트레이 → [종료]**. 실행 중인 작업이 있으면 물어봐요. 끄면 그 작업은 다른 PC로 넘어가거나 다시 대기해요.
- **작업 받기 일시 중지**: 앱은 켜 두되 이 PC가 새 작업을 받지 않게 해요. 목록에는 "일시 중지"로 보여요.
- 앱을 두 번 실행해도 하나만 떠요(두 번째는 첫 창을 앞으로 가져와요).

**자동 시작**
- 켜 두면 Windows에 로그인할 때 **창 없이 트레이로만** 시작해요. 이 PC 상태 → "Windows에 로그인하면 자동으로 시작"에서 켜고 끌 수 있어요.

**알림**
- 앱 창이 숨겨져 있을 때만 트레이 알림으로 알려 줘요(작업 완료 · 실패, 다른 PC로 넘김). 이 PC 상태에서 끌 수 있어요(업데이트 준비 · 연결 해지 알림은 늘 떠요).

**업데이트**
- 앱을 켤 때와 6시간마다 서버에서 새 버전을 확인해서 **자동으로 받아 두고, 다음에 앱을 끌 때 설치**해요. 설치할 때 관리자 권한 창은 뜨지 않아요.
- 바로 쓰려면 트레이 → **업데이트 확인**, 준비가 되면 **[지금 다시 시작]**. 작업이 실행 중이면 "끝나면 다시 시작" 중에서 고를 수 있어요.
- 현재 버전과 상태는 이 PC 상태 맨 아래에서 볼 수 있어요.

## 6. 문제 해결

| 증상 | 해 보세요 |
|---|---|
| 설치할 때 "Windows의 PC 보호" 창이 떠요 | 정상이에요. **[추가 정보] → [실행]**. 받은 곳이 PaperLab 화면의 [PC 앱 받기]인지, 위 SHA-256 확인이 맞는지 보세요. |
| 설치 파일을 받을 수 없거나 "받기가 안 돼요" | 1분 뒤 다시 눌러 보세요(같은 곳에서 너무 자주 받으면 잠시 막혀요). 계속되면 관리자에게 알려 주세요. |
| 앱이 "PaperLab 서버에 연결할 수 없어요" | 서버 PC가 꺼져 있거나 인터넷이 끊겼을 수 있어요. **[다시 시도]**(30초마다 자동으로도 다시 해 봐요). 계속 안 되면 관리자에게 알려 주세요. 그동안 이 PC는 작업을 받지 못하다가 연결되면 이어서 받아요. |
| 로그인 후 앱 창으로 돌아오지 않아요 | 브라우저의 "PaperLab 열기" 확인 창에서 **허용**했는지 보세요. 앱 창의 **[브라우저 다시 열기]** 로 다시 시작해도 돼요. |
| 이 PC 상태에 "! 로그인 필요" | 명령 프롬프트에서 해당 도구(claude · codex · gemini)를 한 번 실행해 로그인한 뒤 **[다시 확인]**. 그동안 그 도구의 작업은 다른 PC가 받아요. |
| "! 업데이트 필요" (claude) | claude를 2.1.259 이상으로 업데이트한 뒤 **[다시 확인]**. |
| "이 PC에서 쓸 수 있는 AI 도구가 없어요" | 4장대로 도구를 설치하고 로그인한 뒤 **[다시 확인]**. |
| "이 앱 버전으로는 작업을 받을 수 없어요" | 앱을 새 버전으로 올려야 해요. 트레이 → **업데이트 확인** → **[지금 다시 시작]**. 받을 수 없으면 새 설치 파일을 받아 설치하면 돼요(설정과 연결은 유지돼요). |
| "이 PC 연결이 해지됐어요" | 다른 곳에서 이 PC의 연결을 해지한 거예요. 이 PC 상태(또는 트레이 [코드로 연결…])에서 새 연결 코드로 다시 연결하세요. |
| "이 PC에서는 연결 정보를 안전하게 저장할 수 없어요" | Windows가 암호화 저장을 허용하지 않는 환경이에요. 연결은 되지만 **앱을 다시 켜면 다시 연결**해야 해요. |
| 작업이 계속 "대기 중 — 켜진 PC 없음" | 이 PC 앱이 켜져 있고(트레이에 아이콘), 연결되어 있고, 일시 중지가 아니고, 해당 도구가 `로그인됨`인지 보세요. |
| 어떤 작업이 다른 PC로 넘어갔어요 | 이 PC의 그 도구가 로그인되지 않았거나 없어서예요. 위 "로그인 필요" 항목을 보세요. |
| 그래도 안 돼요 | 트레이 → **로그 폴더 열기**(`%APPDATA%\PaperLab\logs`의 `main.log` · `worker.log`)를 관리자에게 보여 주세요. 로그에는 논문 내용 · 연결 정보가 들어 있지 않아요. |

**제거와 연결 해지**
- 제거는 Windows 설정 → 앱에서 `PaperLab`을 지우면 돼요. 설정과 연결 정보는 남아서 다시 설치하면 연결이 유지돼요.
- **PC를 더 이상 쓰지 않거나 앱을 지울 때는 웹 설정 → 연결된 PC에서 그 PC를 [연결 해지]** 해 주세요. 앱을 지워도 연결 목록에는 남아 있어요.
- 이 PC에서만 연결을 끊으려면 이 PC 상태 → **[이 PC에서 연결 끊기]**.

## 개발자용

요구 사항: Windows, Node.js 22 이상(서버 PC 빌드도 22 이상을 요구해요), npm.

```powershell
cd desktop
npm ci          # package-lock.json대로 설치
npm test        # node --test "test/*.test.js" — 가짜 서버 · 가짜 CLI로 워커 · 외부 링크 규칙 · main 단위 시험
npm start       # 개발 실행 (데이터는 %APPDATA%\PaperLab-dev — 설치본과 섞이지 않음, 자동 시작 · 업데이트 확인 안 함)
npm run pack    # 설치 파일 없이 폴더로만 만들어 보기
npm run dist    # NSIS 설치 파일 → desktop\dist\PaperLab-Setup-<버전>.exe · .blockmap · latest.yml
```

- 설정 파일은 `electron-builder.config.js`이고 `--config`로 지정해요(`npm run pack` · `npm run dist`가 알아서 해요). 직접 `electron-builder`를 부를 때도 `--config electron-builder.config.js`를 붙여요.
- **서버 주소**는 `deploy/server-pc/server.json`의 `public_url` 한 곳이고, 빌드가 읽어 앱 `package.json`의 `paperlabServer`와 업데이트 주소(`<주소>/downloads/`)에 넣어요. 앱에 주소 입력 칸이 없고 `app-config.json` 같은 파일도 없어요. `npm start`는 환경 변수 `PAPERLAB_SERVER_URL`이 반드시 필요하고 로컬 주소(`127.0.0.1` · `localhost` · `[::1]`)만 돼요. 없거나 운영 주소면 오류 창을 띄우고 시작하지 않아요(배포본은 이 변수를 무시).
- **`PAPERLAB_NO_DETECT=1`**: 실제 CLI의 `--version` · `auth status`를 부르지 않게 하는 설정이에요. 개발 · 시험 때 켜 두길 권장해요(CLI를 찾지도 실행하지도 않고 엔진 없음으로 동작).

  ```powershell
  $env:PAPERLAB_SERVER_URL = "http://127.0.0.1:8765"   # 이 PC의 로컬 개발 서버
  $env:PAPERLAB_NO_DETECT = "1"
  npm start
  ```
- **OneDrive 폴더 안에서는 `npm run dist`가 `EPERM`으로 실패해요.** OneDrive 밖 폴더에서 빌드하세요(서버 PC의 `D:\PaperLab` 경로에서는 해당 없음).
- **앱을 바꾸면 `package.json`의 `version`을 반드시 올리세요.** 같은 버전은 서버 PC가 다시 빌드하지 않고 경고만 남겨요.
- 설치 파일은 **서버 PC가 빌드 · 배포**해요. 관리자가 서버 PC에서 `update.ps1`을 돌리면 `desktop\`이 바뀌었을 때 `npm ci` → `npm run dist`를 하고 `releases` 폴더(`PAPERLAB_RELEASES_DIR`, 기본 `D:\PaperLab\releases`)에 두며, 서버가 `/downloads/`로 내려줘요. 자세한 내용은 [2단계 명세](../docs/specs/phase2-worker-electron.md) 13.7.1절과 [서버 PC 안내서](../deploy/server-pc/README.md).
- 보안 설정(Fuses · 탐색 제한 · IPC 출처 검사 · 외부 링크 규칙)은 명세 13.2 · 13.2.1절. 앱 · 트레이 아이콘은 임시 그림이고 디자인팀 확인을 기다리는 중이에요(`build/`, `scripts/make_icons.py`).
- 비밀값(기기 토큰 · API 키 · DB 주소)은 앱 · 로그 · 저장소 어디에도 두지 않아요.
