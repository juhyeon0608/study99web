## 2. 앱 — "폴더 동기화" 구역 (SD-1)

창 순서: **연결 → 폴더 동기화(새로) → 실행 중인 작업 → 이 PC에서 쓸 AI 도구 → 앱**. 맨 위 알림 상자(`[data-local-banner]`, 2단계 11.8)는 워커 것만 그대로 — 동기화 멈춤은 이 구역 안 상자가 맡음(섞지 않음).

### 2.0 사용자가 직접 정하는 폴더 (사용자 지시 · 명세 7.1 · AC-673a)

| 규칙 | 화면에서 |
|---|---|
| 앱은 폴더를 정하거나 만들지 않음 | 꺼짐 카드에 "시작" 버튼이 없음. 있는 것은 **[폴더 고르기…]** 와(제안 위치가 아직 없을 때만) **[이 위치에 새 폴더 만들기]** 둘뿐 |
| 제안 위치는 시작 위치 · 안내로만 | `C:\Users\<이름>\PaperLab 논문`은 안내 줄 글자와 선택 창이 처음 열리는 위치로만 쓰임. 버튼이 그 경로를 바로 루트로 쓰지 않음 |
| 저장은 두 단계 | ① 선택 창에서 고름 → 검사 → 미리보기 → ② **[시작]**. ①만 한 상태(살펴보는 중 · 미리보기)에는 카드 줄이 "아직 동기화를 시작하지 않았어요"를 말하고, 앱을 끄거나 [취소]하면 아무것도 남지 않고 `off`로 돌아감(표식 · 설정 저장 없음) |
| 새 폴더도 사용자가 | [이 위치에 새 폴더 만들기]를 누르면 빈 폴더 하나만 만들고 **그 폴더에서 선택 창을 엶** — 사용자가 [폴더 선택]을 눌러야 ①이 끝남. 만든 폴더는 선택 창을 닫아도 그대로(빈 폴더 — 지우지 않음) |
| 자동으로 켜지지 않음 | 설치 · 업데이트 · 로그인 · 재로그인 때 스스로 켜지지 않음. **재설치(저장된 설치 ID ≠ 지금 설치 ID — 명세 7.3절 K-33)** 뒤에는 저장된 폴더가 남아 있어도 **꺼짐(`off`)으로 시작**하고, 화면에는 안내 한 줄만: "**전에 쓰던 폴더: {경로} — [다시 연결…]**"(`[data-sync-previous]`). 앱이 그 폴더를 읽거나 스스로 연결하지 않음. **[다시 연결…]도 같은 절차**: 선택 창(전에 쓰던 폴더에서 열림) → 거부 검사 → 미리보기 → [시작](2.5절) — 취소하면 꺼짐 · 안내 그대로. (이 PC를 해지 뒤 같은 설치에서 다시 연결했을 때의 동작과 새 기기로 연결됐을 때 표식 확인은 명세 Q-2 — 팀장 확인 전에는 위와 같이 꺼짐 + 같은 안내로 그림) |
| 바꾸기도 같은 절차 | [폴더 바꾸기…] = 선택 창 → 미리보기 → [이 폴더로 바꾸고 시작](2.2절) |
| 늘 분명한 상태 | 꺼짐 카드 맨 위 상태 줄 **"동기화 폴더를 고르지 않아 동기화하지 않고 있어요."**(`.status-line.bad`) + 칩 "○ 꺼짐", 트레이 둘째 줄 "폴더 동기화 · 꺼짐 (폴더를 고르지 않음)", 웹 "연결된 PC" 줄 "꺼짐 — 이 PC에서 동기화 폴더를 고르지 않았어요" |

### 2.1 꺼짐 (`off`)

```
폴더 동기화
┌ ○ 꺼짐 ─────────────────────────────────────────┐
│ ┌ 동기화 폴더를 고르지 않아 동기화하지 않고 있어요.            ┐ │ ← status-line.bad
│ PC의 논문 폴더 하나를 서재 폴더와 같은 모양으로 맞춰요. PDF만 맞추고,  │
│ 지운 파일은 서재 휴지통(30일)과 Windows 휴지통으로 가요. 폴더를 고르고  │
│ 미리보기에서 [시작]을 눌러야 동기화가 시작돼요.                     │
│ [폴더 고르기…]  [이 위치에 새 폴더 만들기]                          │
│ 추천 위치: C:\Users\홍길동\PaperLab 논문 (아직 없어요). OneDrive ·     │
│ Dropbox · Google Drive가 맞추는 폴더는 고르지 마세요.               │
└──────────────────────────────────────────────┘
```

| 경우 | 보이는 것 |
|---|---|
| 기본 · 제안 위치가 아직 없음 | 위 그림. [폴더 고르기…](primary) + [이 위치에 새 폴더 만들기] |
| 제안 위치가 이미 있음 | [이 위치에 새 폴더 만들기] 없음. 안내 줄 "추천 위치: C:\Users\홍길동\PaperLab 논문 (이미 있어요 — [폴더 고르기…]가 이 폴더에서 열려요)." |
| 제안 위치가 검사를 통과하지 못함(사용자 프로필이 OneDrive 안 등 — AC-673) | [이 위치에 새 폴더 만들기] 없음. 선택 창은 사용자 폴더에서 열림. 안내 줄 "사용자 폴더가 OneDrive 안에 있어 추천 위치가 없어요. OneDrive 밖의 폴더를 골라 주세요." (다른 이유면 "추천 위치를 쓸 수 없어요. 다른 폴더를 골라 주세요.") |
| 재설치 뒤(설치 ID가 다름 — 전에 쓰던 폴더를 앎) · 동기화를 끈 뒤 | 2.0절 "전에 쓰던 폴더: {경로} — [다시 연결…]" 줄 추가(`p.item-meta.sync-note[data-sync-previous]` + `button.btn.sm.ghost[data-sync-reconnect]`). 이 줄은 안내일 뿐 [폴더 고르기…](primary)가 그대로 있음. 경로가 이미 없어도 줄은 보이고 선택 창은 제안 위치에서 열림 |
| 이 PC가 연결 전 · 해지됨 | 버튼 없이 상태 줄 "이 PC가 연결되지 않아 동기화하지 않고 있어요." + `p.item-meta` "위 ‘연결’에서 이 PC를 먼저 연결한 뒤 동기화 폴더를 골라 주세요." |

- [폴더 고르기…]: Windows 폴더 선택 창(`dialog.showOpenDialog`, `properties: ['openDirectory', 'createDirectory']`), 제목 "동기화할 논문 폴더 고르기", 확인 버튼 글자 "폴더 선택", **시작 위치 = 제안 위치**(없으면 사용자 폴더 — 바탕 화면 · 문서로 시작하지 않음, 명세 7.1). 고른 뒤 검사 → 통과하면 첫 검사(2.5절), 아니면 3장 거부 상자. 선택 창에서 [취소]하면 아무 일도 없음.
- [이 위치에 새 폴더 만들기]: 확인 창 없이(버튼 글자가 말함) 제안 위치에 빈 폴더를 만들고 → 그 폴더를 연 선택 창 → 사용자가 [폴더 선택]. 만들기에 실패하면 `.status-line.bad[role=alert]` "폴더를 만들지 못했어요. [폴더 고르기…]로 다른 곳을 골라 주세요."
- 제안 위치도 3장 거부 검사를 먼저 거침 — 통과하지 못하면 [이 위치에 새 폴더 만들기]를 그리지 않음(AC-673).

### 2.2 켜짐 — 카드

```
폴더 동기화
┌ PaperLab 논문  ✓ 최신                           [지금 맞추기] ┐
│ C:\Users\홍길동\PaperLab 논문                                  │
│ ┌ 마지막 동기화 오후 3:10 · 서재와 같아요                     ┐ │  ← status-line
│ 맞춘 파일 312개                                                │
│ [폴더 열기] [일시 중지] [폴더 바꾸기…]            동기화 끄기   │
└──────────────────────────────────────────────┘
▸ 맞추지 못한 파일 (4)                                        ← 있을 때만
보관함 12.4MB — Windows 휴지통으로 보내지 못한 파일이에요. [보관함 열기]   ← 0이면 없음
[✓] 창이 숨어 있을 때 동기화 알림 보이기 (충돌 사본 · 번역 지움 · 보관함)
```
(시안: 9장 `app.html`)

- 맞추는 중이면 상태 줄 아래 `.progress`(완료 수 / 이번 묶음 전체 수). 전체 수를 모르면(첫 검사 초반) `.progress.indeterminate`.
- [지금 맞추기]: 전체 다시 맞추기(명세 6.6). 맞추는 중 · 멈춤 · 일시 중지에는 `disabled`. 누르면 상태가 `scanning`으로 바뀌어 줄이 대신 알림.
- [일시 중지] ↔ [다시 시작](`aria-pressed`). 일시 중지는 확인 창 없음.
- [폴더 열기]: 탐색기로 루트. 루트를 잃었으면 숨김.
- [폴더 바꾸기…]: 2.0절 절차 그대로 — 선택 창(지금 폴더의 부모에서 열림) → 검사 → 미리보기(제목 "동기화 폴더를 바꾸기 전에 확인해 주세요", 경로 줄 "지금: {옛 경로} → 새 폴더: {새 경로}") → **[이 폴더로 바꾸고 시작]**. 이 버튼을 누를 때 옛 폴더 동기화를 끄고 새 폴더를 저장(명세 7.3 "끄기 + 새로 첫 연결"). 선택 창 · 미리보기에서 취소하면 **아무것도 바뀌지 않고 옛 폴더 동기화가 계속**. 새 폴더를 살펴보는 동안 옛 폴더는 일시 중지했다가 취소하면 다시 시작(개발 재량 — 12장 요청 14). 옛 폴더의 파일은 그대로 남음(미리보기 안내 줄 "지금 폴더의 파일은 그대로 남고, 더는 맞추지 않아요.").
- [동기화 끄기](ghost · 빨강): 네이티브 확인 "폴더 동기화를 끌까요?" / 자세히 "이 PC의 파일과 서재는 그대로 남아요. 다시 쓰려면 폴더를 다시 고르고 미리보기에서 [시작]을 눌러야 해요." / [끄기] [취소](기본 = 취소). 끈 뒤 카드는 2.1절(상태 줄 "동기화 폴더를 고르지 않아 …" · 안내 줄 "전에 쓰던 폴더: … — [다시 연결…]").
- `item-title`은 루트 마지막 폴더 이름(웹에 보이는 `root_label`과 같은 글자), 전체 경로는 `sync-root` 줄.

### 2.5 첫 검사 · 시작 흐름

1. **사용자가** [폴더 고르기…](또는 [이 위치에 새 폴더 만들기] → 선택 창)에서 폴더를 고름 → 거부 검사 통과 → `scanning`(첫 연결) — 카드 상태 줄 + 진행 막대 + [취소]. 이 단계는 **읽기만**(표식 · 설정 저장 · 서버 `sync/start` 없음 — AC-673a).
2. 검사 · 스냅숏이 끝나면 `preview` → **미리보기 창을 바로 엶**(창이 숨어 있으면 풍선 "처음 맞추기 미리보기가 준비됐어요. 눌러서 확인해 주세요." — 끌 수 없는 알림).
3. **[시작]을 누를 때 처음으로** 루트 저장 · 표식 만들기 · 서버 `enabled: true` → `syncing`. 끝나면 풍선(동기화 알림 켜짐일 때) "처음 맞추기를 마쳤어요 — 연결 286 · 올림 12 · 받음 40".
4. [취소](미리보기 · 살펴보는 중) 또는 그 사이 앱 종료 · 업데이트 재시작 → `off`로 돌아감, 서버 · 파일 · 설정 변화 0(AC-671 · AC-673a). 취소했을 때 `.status-line[role=status]` "처음 맞추기를 취소했어요. 폴더는 저장하지 않았고 파일도 바꾸지 않았어요." 한 번. 다시 켜면 1번부터.

| kind | 굵은 첫 문장 | 이어지는 글 |
|---|---|---|
| `disk` | 이 PC 디스크 공간이 모자라요. | 받을 파일 {152MB}와 여유 1GB가 필요한데 {C:} 드라이브에 {800MB}만 남았어요. 공간을 비운 뒤 [다시 살펴보기]를 누르거나, 다른 드라이브의 폴더를 골라 주세요. |
| `storage` (K-30 · `upload_budget_limit: "storage"`) | 서재 저장 공간이 모자라요. | 올릴 파일 {2.4GB} · 남은 공간 {1.1GB}. 모든 사용자가 함께 쓰는 공간이라 관리자에게 알려 주세요. |
| `user` (K-30 · `upload_budget_limit: "user"`) | 내 올리기 한도({2GB})를 넘어요. | 올릴 파일 {2.4GB} · 남은 한도 {1.1GB}. 올릴 PDF를 줄이거나(동기화 폴더 밖으로 옮김) 관리자에게 한도를 늘려 달라고 해 주세요. 서재 휴지통을 비워도 한도가 늘어요. |
| `db` (**K-46 — 서재 데이터베이스 예산, 코드 `sync-look.js` `previewBlock` 그대로**) | **서재 데이터베이스 공간이 모자라요.** | 올릴 논문 {120}편 · 예상 {31MB} · 남은 공간 {20MB}. 모든 사용자가 함께 쓰는 공간이라 관리자에게 알려 주세요. (`storage` 막힘과 같은 형식 — 숫자는 올릴 논문 편수 · 예상 증가량 · 남은 예산 `budget_bytes`, 용량 단위는 `fmtBytes`) |

- 막혔을 때 [시작]을 누르면(초점 유지 — `aria-disabled`) 첫 막힘 상자로 초점(`tabindex=-1`)을 옮겨 다시 읽힘. 4단계 `aria-disabled` 규칙 그대로.
- 막힘 상자 순서(K-46): **디스크 → 서재 저장 공간(`storage` 또는 `user`) → 서재 데이터베이스(`db`)**. 해당하는 이유를 **모두** 위에서부터 차례로 보임. `db`는 서버가 첫 쪽 응답에 `db`를 줄 때만 계산(명세 7.2절 · 14.1절).
- [다시 살펴보기](`.modal-foot .left`, ghost — 막혔을 때만): 디스크 여유 · 예산을 다시 받고 계획을 다시 계산(사용자가 파일을 옮긴 뒤). 진행 중엔 "살펴보는 중…" + `disabled`.
- 막힘이 `user`이고 사용자의 서재 휴지통에 PDF가 있으면(`snapshot` 첫 쪽의 `trash_bytes` — 확정 K-34, 12장 요청 6. 한도 숫자 {2GB}는 같은 응답의 `user_cap_bytes`) 이어지는 글 끝을 "서재 휴지통({12MB})을 비워도 한도가 늘어요."로.
- 미리보기와 [시작] 사이에 예산이 줄면 서버가 다시 막음(명세 7.2-2 마지막 줄) → 2.3절 `storage_full` 줄 · 2.4절 상자가 이어받음.

### 4.3 버튼 · 키보드

- [취소](기본 버튼 모양) · [시작](primary — 이 버튼이 루트를 저장하는 유일한 곳. 바꾸기 흐름에서는 글자 "이 폴더로 바꾸고 시작"). [시작] 바로 위 `p.small.muted` "[시작]을 누르면 이 폴더를 동기화 폴더로 저장하고 맞추기 시작해요." **처음 초점 = 제목(`h3[tabindex=-1]`)** — 화면 읽기가 제목 · 내용부터 읽고, Enter를 눌러도 시작되지 않음.
- Esc · ✕ = [취소](2.5절 4번). 상태 창의 Esc(창 닫기)보다 먼저 받음(`cancel` 이벤트에서 `stopPropagation` — 개발팀).
- 상태 창을 닫았다 다시 열면(앱은 켜진 채) `preview` 상태라 창이 다시 열림(계획은 엔진 메모리에). 앱을 끄면 계획 · 고른 폴더는 사라지고 `off`(12장 요청 16).

## 5. 대량 삭제 · 루트 이상 확인 창 (SD-4, 명세 12.2 · 12.3 · K-12)

`dialog.modal.sync-dialog#sync-confirm[data-confirm-kind]`. **버튼 셋 + 보조 링크 하나(팀장 결정 K-31 — 명세 12.2 그대로)**: **[서재에서도 지우기(휴지통으로)] · [되돌리기] · [나중에]** + 보조 링크 **[동기화 끄기]**. **Esc · ✕ = [나중에]**(1시간 뒤 다시 물음). 서재 → PC 방향은 명세 12.2 문구를 기준으로 같은 모양(5.1절 표). (옛 안 "계속 / 되돌리기 / 끄기"는 버림.)

### 5.1 세 종류

| kind | 제목 | 본문 | 지우기 버튼 (`continue`) | 되돌리기 버튼 (`revert`) |
|---|---|---|---|---|
| `local_delete` (PC → 서재) | 파일 {12}개를 지웠어요 — 서재에서도 지울까요? | 이 PC 동기화 폴더에서 30초 사이에 파일 {12}개가 사라졌어요(맞추던 파일의 {4}%). 실수일 수 있어 지우기만 잠깐 멈췄어요. 다른 변경은 계속 맞춰요. | **서재에서도 지우기** `(휴지통으로)` — 서재 휴지통(30일) · 다른 PC는 Windows 휴지통 | **되돌리기** — 서재에서 다시 받아 PC 원래 자리에 둠 |
| `remote_delete` (서재 → PC) | 서재에서 논문 {12}편이 휴지통으로 갔어요 | 이 PC의 파일도 Windows 휴지통으로 보낼까요? 지운 곳: {웹 · 연구실 PC}(피드의 `deleted_by_label` — K-34). 실수로 여러 편을 지웠을 수 있어 이 PC 파일은 아직 그대로 두었어요. | **이 PC에서도 지우기** `(Windows 휴지통으로)` | **서재에 되살리기** — 엔진이 `files/add`를 다시 보내 서재 휴지통에서 되살림(명세 K-32, 이 PC 파일은 그대로) |
| `root_anomaly` (한 번에 절반 이상 사라짐) | 파일이 한꺼번에 많이 사라졌어요 ({312}개 중 {180}개) | 폴더를 옮겼거나 드라이브에 문제가 있을 수 있어 동기화를 멈췄어요. 직접 지운 게 맞으면 서재에서도 지울 수 있어요. | **서재에서도 지우기** `(휴지통으로)` | **되돌리기** |

- 괄호 `(휴지통으로)` · `(Windows 휴지통으로)`는 버튼 글자 뒤 작은 글자(`span.small`) — 새 클래스 없음. 화면 읽기는 버튼 전체를 한 이름으로 읽음.
- [나중에] · [동기화 끄기]는 세 종류 모두 같은 글자.
- `root_anomaly`가 [서재에서도 지우기]와 같은 버튼 구성을 쓰는 것은 명세 12.3(가정)에 한 줄로 반영됨.

공통:
- 본문 아래 `ul.sync-file-list` — 상대 경로 처음 5개 + `li.muted` "외 {n}개"(`remote_delete`는 서재 파일 이름). 목록이 길면 상자 안에서 스크롤(높이 약 6줄).
- 안전 안내 `.notice[data-tone=info]`: `local_delete` · `root_anomaly` "서재에서 지우면 휴지통에 30일 남아 되살릴 수 있어요. 다른 PC의 파일은 Windows 휴지통으로 가요." / `remote_delete` "이 PC에서 지우면 Windows 휴지통으로 가요. 서재 휴지통에서 되살리면 다시 받아요."
- **보조 링크 [동기화 끄기]**(`.modal-foot .left`, `.btn.sm.ghost` — 링크처럼 보이는 가장 약한 버튼): 기다리던 삭제를 보내지 않고(PC → 서재: PC는 지운 채 서재는 그대로 / 서재 → PC: PC 파일 그대로) 동기화를 끔 — 2.2절 끄기 확인 창을 한 번 더 거침. 파일 잃음 없음. 위 세 버튼보다 눈에 덜 띄게(빨강 아님 — 파괴 동작이 아니라 멈추는 동작).
- **[나중에]와 Esc · ✕는 같은 동작**: 아무것도 보내지 않고 `waiting_confirm` 그대로 — 트레이 · 2.4절 상자에 남고 **1시간 뒤 다시 묻고**(그때도 정하지 않으면 1시간마다 풍선 — 명세 12.2). ✕의 `aria-label="나중에"`. IPC `sync-confirm {choice: "later"}`.
- 처음 초점 = 제목(`tabindex=-1`). 기본 버튼 없음(Enter로 아무것도 일어나지 않음, 세 버튼 모두 primary 아님). Tab 순서: [동기화 끄기] → [나중에] → [되돌리기] → [지우기].
- 누르면 버튼 `disabled` + 창 닫힘 → 상태 줄이 결과를 알림: "서재 휴지통으로 옮겼어요 (12개)" · "12개를 되돌리는 중이에요" · "이 PC 파일 12개를 Windows 휴지통으로 보냈어요" · "서재에서 12편을 되살리는 중이에요".
- 한 번에 묶음 하나만 물음. 기다리는 동안 새 대량 삭제가 오면 같은 창의 개수를 늘림(다시 열지 않음).

## 6. 맞추지 못한 파일 — 이유 문구 (SD-7, 명세 6.5 · 8장 · 9.3 · 9.7 · 12.4)

`details.sync-more[data-sync-problems]` 요약 "맞추지 못한 파일 {n}" — 0이면 그리지 않음. 펼친 상태는 창을 다시 그려도 유지(`open` 기억). 이유마다 `li[data-problem]` > `p.sync-reason` + 파일 5개 + "외 n개". 파일 줄 [위치 열기]는 PC에 있는 파일만(서재에만 있는 것 — `*_down` — 은 버튼 없음).

| code | 문구(`p.sync-reason`) |
|---|---|
| `too_long_down` | 경로가 너무 길어 이 PC에 만들지 못했어요(250자 넘음). 서재에는 그대로 있어요. 폴더 이름을 줄여 주세요. |
| `too_long_local` | 경로가 너무 길어 옮기거나 바꾸지 못해요(250자 넘음). 서재에는 올렸어요. 폴더 이름을 줄여 주세요. |
| `folder_name_too_long` | 폴더 이름이 100자를 넘어 이 폴더와 안의 파일은 맞추지 않아요. 이름을 줄여 주세요. |
| `file_name_too_long` | 파일 이름이 200자를 넘어 맞추지 않아요. 이름을 줄여 주세요. |
| `bad_name_local` | Windows나 서재에서 쓸 수 없는 이름이에요(예: CON · NUL, 끝의 점 · 공백, \ / : * ? " < > \|). 이름을 바꿔 주세요. |
| `bad_name_server` | 서재의 이름을 이 PC에서 쓸 수 없어 만들지 않았어요. 서재에는 그대로 있어요. |
| `case_conflict` | 같은 폴더에 대소문자만 다른 이름이 있어 하나만 맞췄어요. 한쪽 이름을 바꿔 주세요. |
| `not_pdf` | 이름은 .pdf인데 PDF 파일이 아니에요. |
| `empty_file` | 빈 파일(0바이트)이에요. |
| `too_big` | 100MB를 넘는 PDF는 서재에 올릴 수 없어요. |
| `hidden` | 숨김 · 시스템 파일이라 맞추지 않아요. |
| `temp_name` | 임시 파일 이름이라 맞추지 않아요(점 · ~$로 시작하거나 .tmp · .part 등으로 끝남). |
| `link` | 바로 가기 연결(심볼릭 링크 · 정션)이라 따라가지 않아요. 안의 파일도 맞추지 않아요. |
| `duplicate_copy` | 이 PC에 같은 내용의 파일이 이미 있어 맞추지 않았어요. 필요 없으면 지워도 서재에는 영향이 없어요. |
| `busy` | 열려 있는 파일이라 나중에 바꿀게요. 다른 프로그램에서 닫아 주세요. |
| `trash_aborted` | Windows가 휴지통 보내기를 중단했어요 — 잠시 뒤 다시 해요. 파일을 연 프로그램이 있으면 닫아 주세요. 계속 안 되면 보관함으로 옮겨요. |
| `trash_timeout` | Windows 휴지통이 2분 안에 답하지 않았어요 — 잠시 뒤 다시 해요. |
| `read_only` | 읽기 전용 파일이라 바꾸거나 Windows 휴지통으로 보내지 않았어요. 파일 속성에서 읽기 전용을 풀어 주세요. |
| `writing` | 계속 바뀌고 있는 파일이라 다 쓰일 때까지 기다려요. |
| `folder_kept` | 서재에서 지운 폴더에 다른 파일이 남아 있어 폴더를 두었어요. 다시 서재 폴더로 만들지는 않아요. |
| `disk_full` | 이 PC 디스크 공간이 모자라 받지 못했어요. 공간을 비우면 이어서 받아요. |
| `retrying` | 잠시 실패해 다시 시도하는 중이에요(다음 시도 {오후 3:40}). |
| 모르는 code | 맞추지 못했어요. 로그 폴더를 관리자에게 보여 주세요. |

- 순서: 사용자가 고칠 수 있는 것(이름 · 길이 · 읽기 전용 · 열림) → 정보(제외 · 중복 · 폴더 남김) → 재시도.
- (2026-10-14 전체 오류 점검) 휴지통 보내기 실패 문구는 **"잠겼다"고 단정하지 않음** — Electron은 잠김뿐 아니라 그 밖의 거절도 "중단"으로 돌려주므로 `trash_aborted`("Windows가 휴지통 보내기를 중단했어요 …", 재시도만 — 보관함으로 옮기지 않음) · `trash_timeout`(2분 무응답, 재시도만) 두 코드로 나눔. 옛 코드 `trash_locked`는 없음. `sync-look.js`에는 이 밖에 `trash_parse_failed` · `trash_failed` · `cloud_only` · `attr_unknown` 문구도 있으나 이 표에는 아직 옮기지 않았음(디자인팀 남은 일).
- 저널 상한 500개(명세 6.3)를 넘으면 요약 끝에 " (최근 500개)".

## 7. 트레이 (SD-5) · 알림 (SD-6)

### 7.1 아이콘 (2단계 4종 그대로 — 새 파일 없음)

워커 상태와 동기화 상태를 합쳐 **위에서부터 첫 번째**:

| 순서 | 아이콘 | 조건 |
|---|---|---|
| 1 | `error`(주황 ▲ !) | 2단계 error 조건 **또는** 동기화 `waiting_confirm` · `root_missing` · `account_mismatch` · `storage_full` · `update_required` · `preview` |
| 2 | `running`(초록 ▶) | 작업 실행 중 **또는** 동기화 `syncing` · `scanning` |
| 3 | `paused`(회색 ❙❙) | 작업 받기 일시 중지 **또는** 동기화 일시 중지(켜져 있는 것이 모두 멈춤일 때만 — 하나라도 돌면 2 · 4) |
| 4 | `idle` | 그 밖 |

(`preview`를 오류 아이콘에 넣은 이유: 사용자가 결정해야 진행됨. `offline`은 이미 2단계 error)

### 7.2 툴팁 (두 줄 — `\n`, 128자 안)

`PaperLab — {2단계 문구}` + 줄바꿈 + `폴더 동기화: {짧은 상태}`(꺼짐이면 "폴더 동기화: 꺼짐 (폴더를 고르지 않음)"). 짧은 상태 = 7.3절 메뉴 줄의 "폴더 동기화 · " 뒤와 같음. 예: "PaperLab — 대기 중\n폴더 동기화: 최신 (오후 3:10)". Windows 툴팁의 줄바꿈 표시는 12장 확인 5.

### 8.2 동작 · 확인 창 · 토스트

| 동작 | 확인 창(`confirmDialog`) | 성공 토스트 |

- 영구 삭제 · 비우기 확인 창은 **처음 초점을 [취소]에**(되돌릴 수 없음). 지금 `confirmDialog`는 확인 버튼에 초점을 주므로 `{focus: "cancel"}` 같은 인자 추가 — **확정(명세 K-35 · 22장 `ui.js`, 이름은 개발팀 재량, 기존 호출 불변)**(12장 요청 4).
- 처리 중 그 줄 버튼 `disabled` + 누른 버튼에 스피너. 끝나면 줄을 지우고 **초점을 다음 줄의 [되살리기]**(없으면 이전 줄, 그것도 없으면 빈 상태 제목 `tabindex=-1`).
- 영구 삭제 · 비우기 뒤 `refreshUsage()`(저장 공간 막대가 줄어듦), 되살리기 뒤 `refreshAll()`(사이드바 개수).
- 동기화 PC 쪽 말은 영구 삭제 창에 넣지 않음 — PC 파일은 이미 Windows 휴지통에 있으므로 바뀌는 것이 없음.

### 10.2 상세 "파일 이름" (SW-4)

- "정보" 탭 `dl.kv`의 링크 줄 다음: `<dt>파일 이름</dt><dd data-file-name title="PC 폴더 동기화에서 쓰는 이름이에요. 이름은 PC에서 바꿔 주세요.">{file_name}</dd>`. PDF가 있고 `file_name`이 있을 때만. 읽기 전용(버튼 없음 — K-15).
- `dt`를 "PC 파일 이름"이 아닌 "파일 이름"으로 한 이유: 지금 `.kv` 첫 칸이 74px이라 "PC 파일 이름"은 두 줄로 꺾임. 뜻은 `title`이 말함.

### 10.3 저장 공간 (SW-5)

- 설정 "계정" `usage-num`: "전체 {used} / {limit} · 내 PDF {mine} · 휴지통 {trash}"(`trash_bytes` 0이면 뺌).
- 그 아래 `div.usage-trash`(휴지통이 있을 때만): "휴지통의 PDF도 저장 공간을 써요. 비우면 바로 줄어요." + [휴지통 보기](ghost — 설정 창을 닫고 `#/trash`).
- 사이드바 막대 `title`: "모든 사용자가 함께 쓰는 저장 공간이에요 · 내 PDF {mine} · 휴지통 {trash}".
- 동기화 올리기 한도(2GB)는 **웹에 보이지 않음**(Q-1 — 웹 업로드에는 적용되지 않으므로 헷갈림). 앱 미리보기 · 멈춤 문구에서만.

### 10.4 `충돌 사본` 태그 · 사본 안내 (SW-6)

- 서버가 만드는 태그 이름은 정확히 `충돌 사본`, 색은 **빈 값**(기본)으로 만듦. 화면은 이름이 `충돌 사본`이고 `color`가 비었을 때만 `data-tag-kind="conflict"` → `.chip` · `.tag-dot`이 경고 톤(`--warn-soft` / `--warn` — 두 테마 AA). 사용자가 색을 고르면 그 색이 이김.
  - 왜 고정 색(`#f08c00` 등)을 쓰지 않나: 지금 태그 색은 글자색으로 바로 들어가 흰 바탕에서 주황 대비가 약 2.5:1(AA 미달), 어두운 테마도 일부 색이 미달. 토큰을 쓰면 두 테마 모두 맞음.
- 서재 상세(그 태그가 있는 논문): `div.notice.detail-note[data-tone=info][data-conflict-copy]` "**충돌 사본이에요.** 같은 PDF를 두 곳에서 고쳐서 남겨 둔 다른 쪽 내용이에요. 원래 파일은 같은 폴더의 ‘{원래 이름}’이에요. 필요 없으면 휴지통으로 옮겨 주세요." — `{원래 이름}`은 `file_name`에서 " (충돌 사본 …)" 괄호를 뗀 것(순수 함수 `conflictOriginal(fileName)`, 못 떼면 그 문장 뺌).
- 사이드바 태그 목록 · 태그 필터는 지금 그대로(사용자가 태그로 사본만 모아 볼 수 있음 — 명세 10.4).

### 10.5 번역 지움 안내 (SW-7, 확정 K-28 · 명세 10.5)

판정: **`GET /api/papers/{pid}`의 `translation_cleared_at`이 있고 전체 번역 행이 없을 때만**. 닫기 버튼 없음 — 새 번역을 시작하면 서버가 값을 비워 사라짐.

| 곳 | 모양 · 문구 |
|---|---|
| 읽기 화면 "설명·번역" → 전체 번역(`explain.js` `drawPaper`, 번역 없음 화면 `.ai-cta` 맨 앞) | `div.notice[data-tone=info][data-tr-cleared]` "**PDF가 바뀌어 번역을 지웠어요.** 다시 번역하려면 [전체 번역 시작…]을 눌러 주세요." — 그 아래 지금 CTA(“이 논문을 통째로 번역해요” · [전체 번역 시작…]) 그대로 |
| 서재 상세 패널(`[data-oa-after]` 다음) | `div.notice.detail-note[data-tone=info][data-tr-cleared]` "**PDF가 바뀌어 번역을 지웠어요.** 다시 번역하려면 읽기 화면의 설명·번역 → 전체 번역에서 [전체 번역 시작…]을 눌러 주세요." (**AD-5 채택 — 확정 K-37**) |
| 웹 [PDF 바꾸기]로 바꿨을 때(같은 기록 — 명세 10.5 넷째 줄) | 위 두 곳이 똑같이 보임 + 바꾼 직후 토스트 "PDF를 바꿨어요. PDF가 바뀌어 번역을 지웠어요."(`pdf/complete` 응답의 `translation_cleared`가 true일 때 — 확정 K-34, 12장 요청 5) |
| 한 번에 여러 편(웹에서 여러 편의 PDF가 한꺼번에 바뀌는 흐름이 생기면) | 토스트 "PDF가 바뀌어 번역 {n}편을 지웠어요." (지금 웹에는 그런 흐름이 없음 — 문구만 정해 둠) |

- 명세 문구의 "[전체 번역]"은 지금 버튼 이름 **[전체 번역 시작…]**으로 씀(사용자가 화면에서 찾는 글자와 같게).
- 앱 쪽은 7.4절 풍선(올린 PC에만 — 받는 PC에는 없음, AC-639).

### 10.6 가져오기 중복 — 휴지통에 같은 논문 (SW-8, K-40 · 코드 `dialogs.js` `trashedDuplicate` · 서버 `TRASHED_DUP` 그대로)

서재에 넣으려는 논문(업로드 · 논문 추가 · 직접 입력 · 논문 찾기의 [서재에 추가])이 **휴지통에 이미 있으면** 새 논문을 만들지 않고(서버가 `trashed: true`로 답함 — 명세 11.1 · 14.2) 이 안내를 보임.

| 곳 | 보이는 것 |
|---|---|
| 토스트(모든 경로 공통) | **"휴지통에 같은 논문이 있어요 — ‘{제목}’"** + 버튼 **[되살리기]**(`.toast-action`, 8초 — 마우스가 위에 있거나 버튼에 초점이 있으면 기다림). 제목이 없으면 **"휴지통에 같은 논문이 있어요"**만. 제목은 `esc()`로만 넣음 |
| [되살리기] | `POST /api/trash/restore {ids: [그 논문 id]}` → 토스트 "되살렸어요"(`restoreFromTrash` — 이름이 겹치면 " · 1편은 같은 이름이 있어 이름 끝에 (2)를 붙였어요", 원래 폴더가 없으면 " · 1편은 원래 폴더가 없어 ‘폴더 없음’에 두었어요" 가 붙음, 8.2절과 같음) + 서재 · 사이드바 개수 다시 그림. 실패 → `errorToast` |
| PDF 올리기 창의 그 파일 줄 | 상태 기호 **＝**(중복), 줄 글 **"{파일 이름} · 휴지통에 같은 논문이 있어요"**(서버가 준 `note`) + 같은 토스트. 새 논문은 만들지 않았으므로 끝 요약의 "건너뜀"에 셈 |
| 직접 입력 · 논문 추가 | 같은 토스트 한 번만(오류 토스트 "같은 논문이 이미 서재에 있어요"는 **살아 있는** 논문과 같을 때만 — 바뀌지 않음) |

- 이 안내는 **새 논문을 만들지 않는 경우**만. 동기화로 PC 파일이 올라올 때 같은 DOI의 휴지통 논문이 있고 PDF가 다르면(서버 `trashed_duplicate_id`) 새 논문으로 올라가고 이 안내는 **아직 없음**(후속 — 명세 3장 · 16.5절 #16).
- 서재 표시용 검사(인용 그래프 "서재에 있음" 등)는 휴지통 논문을 "서재에 없음"으로 봄 — 이 안내와 무관(명세 11.1).
