# 논문 쓰기 — 그림 · 표 · 캡션 · 목록 · 단축키 도움말 (2026-10-16)

사용자 요청: "논문 쓸 때 표도 넣고 그림도 넣어야 하는데 캡션 같은 기능이 없어", "단축키나 명령어 설명이 있어야 할 거 같아.
그리고 글머리 목록 추가 못 하나? 수정이나", 쓰는 중에 그림을 넣을 수 있어야 함.

원고는 지금처럼 **마크다운 글 하나**(paperlab.manuscripts.content)로 저장한다. 그림 · 표 · 캡션 · 목록은 모두 마크다운
문법으로 원고 글에 들어가고, 미리보기 · 워드(.docx) · 한글(.hwpx) · 마크다운 내보내기가 같은 블록 목록(writing.js
`buildDocument`)으로 만든다. DB 마이그레이션은 없다.

## 1. 쓰는 법 (원고 마크다운)

| 쓰는 법 | 결과 |
|---|---|
| `![설명](fig:0123456789abcdef.png)` (한 문단에 이것만) | 그림 + 아래에 **그림 1.** 설명 |
| `![설명](fig:…){#fig:이름}` | 위 + 참조 이름 |
| `표: 제목 {#tbl:이름}` (표 바로 위 한 줄, 영문 `Table: …`) | 표 위에 **표 1.** 제목. 표 바로 아래 줄에 써도 됨(Pandoc 방식) |
| `\| 칸 \| 칸 \|` + `\| --- \| :-: \|` | 표 (`:-:` 가운데, `--:` 오른쪽). 칸 안의 `\|`는 `\\|` |
| `@fig:이름` · `@tbl:이름` (본문) | "그림 2" · "표 1" (영문 원고는 "Figure 2" · "Table 1"). 없는 이름은 주황색 `@fig:x?` |
| `- 항목` · `1. 항목` · 들여쓴 `  - 하위` | 글머리 · 번호 · 하위 목록 (글머리 기호는 단계마다 • ◦ ▪) |

- 번호는 원고에 나온 **순서대로** 매긴다(맨 바깥 문단만). 그림 · 표를 옮기거나 지우면 미리보기 · 내보내기 번호가 다시 매겨진다.
- 캡션 머리말은 한글 원고(본문에 한글이 있으면)는 "그림 1." · "표 1.", 아니면 "Figure 1." · "Table 1.". 머리말은 굵게.
- 상호 참조는 인용 표시(`[@키]`)와 겹치지 않게 대괄호 없이 쓴다(`[@fig:…]`로 쓰면 인용으로 읽힘). 앞에 글자 · 숫자 · `@`가
  붙으면(이메일 등) 참조가 아니다.
- `fig:` 주소가 아닌 그림(`![x](https://…)`)은 지금처럼 설명 글자로만 나온다(CSP가 바깥 그림을 막음).

## 2. 그림 저장 (서버)

| 항목 | 값 |
|---|---|
| R2 키 | `users/{uid}/figures/{원고 id}/{16진수 16자리}.{png\|jpg\|gif}` — `storage.figure_key` · `_FIGURE_KEY_RE`, `check_user_key`가 받음 |
| 올리기 | `POST /api/manuscripts/{id}/figures` (multipart `file`) → `{name, ref: "fig:{name}", width, height, size}` |
| 받기 | `GET /api/manuscripts/{id}/figures/{name}` — 내 원고일 때만, 형식은 다시 매직 바이트로 판정한 그림 MIME, nosniff |
| 검사 | 매직 바이트로만 형식 판정(PNG · JPEG · GIF), 머리글에서 가로 · 세로(1~20000px), 한 장 10MB, 원고 하나 200장 · 300MB. 워드(python-docx)가 읽는 그림만(`figures.word_readable` — JFIF · Exif 머리글 없는 JPEG는 400) |
| 저장 공간 | 올리기 전에 `ensure_space`(R2 95% 규칙, PDF · 원본 올리기와 같음). 그림 바이트는 `FigureSizeCache`(users/ 목록 중 그림 키 합계, 5분 캐시 + 올릴 때 바로 더함)로 R2 사용량(`storage_used` → 설정의 사용량 · 동기화 예산)에 더한다 |
| 지우기 | 원고를 지우면 커밋 뒤 그 원고의 그림 폴더를 지운다. 원고 글에서 그림 줄만 지운 그림은 원고를 지울 때까지 남는다(실행 취소로 되살릴 수 있게) |
| 서명 주소 | 만들지 않는다(`UserStorage._pdf_only`가 거부). 화면은 인증된 GET으로 받아 `blob:` 주소로 보인다(CSP `img-src 'self' data: blob:` 그대로) |

**DB 표 대신 R2 + 원고 글의 `fig:` 참조를 고른 이유**: 원고는 마크다운 글 하나로 자동 저장(0.8초마다 PATCH)되므로 그림
바이트를 원고 행에 넣으면 저장이 무거워진다. 큰 바이너리는 PDF · 원본 파일처럼 R2에 두는 지금 설계와 같고, 그림의
위치 · 순서 · 캡션은 원고 글이 이미 들고 있어 따로 행을 둘 필요가 없다(행이 없으니 RLS · 마이그레이션도 없음).
사용자 분리는 키 규칙(users/{uid}/) + 원고 소유 확인(`get_manuscript`는 user_id 조건)으로 한다.
알려진 한계: 그림 줄을 다른 원고로 복사하면 그 원고에서는 "그림을 찾을 수 없어요"로 보인다(그림은 원고별 폴더).
관리자 고아 검사(`admin.find_orphans`)는 figures 키를 건드리지 않는다.

화면은 WebP · BMP · AVIF 등 워드 · 한글이 못 읽는 그림을 브라우저에서 PNG로 바꿔 올린다(writetools.js). JPEG도 6번째 바이트부터
`JFIF` · `Exif`가 아니면(어도비 XMP 먼저 · CMYK APP14 · ICC 먼저 · 바로 DQT) 브라우저에서 JPEG로 다시 저장해 올린다(`writeedit.jpegNeedsReencode`).
그림 올리기 · 받기는 오래 걸릴 수 있는 요청(api.js `LONG_RE`)이라 3초가 넘어도 '서버에 연결하는 중' 띠를 띄우지 않는다. 붙여넣기는
클립보드에 **글이 없고 그림만** 있을 때만 그림으로 넣는다(워드에서 복사한 글은 그대로 붙여넣기).

## 3. 내보내기 (writer.py)

블록 (화면 → `POST /api/export-document`, `manuscript_id` 함께):

- `{"type": "figure", "src": 그림 이름, "alt", "caption": [런…]}` — 서버가 `figures.attach_images`로 **그 사용자의 그 원고 폴더에서만**
  그림을 읽어 `image`를 채운다. 화면이 보낸 `image` 값은 지운다. 못 읽으면 "[그림을 찾을 수 없어요]".
  같은 그림 이름은 한 번만 읽고(같은 image를 씀, 한글 BinData · 워드 media에도 한 번만), 읽은 합계는 원고 그림 상한(300MB)까지 — 넘으면 나머지는 자리 글.
  워드가 못 읽는 그림(검사 전에 올린 이상한 JPEG 등)은 내보내기 전체를 실패시키지 않고 자리 글 + 경고 `figure-unreadable`(화면 토스트).
- `{"type": "table", "rows": [[[런…]…]…], "header": true, "align": [...], "caption": [런…]}` — 줄마다 칸 수를 맞춤, 최대 500줄 × 30칸.
  캡션 · 칸 안의 각주 런은 글자로 바꾼다.

| | 워드(.docx) | 한글(.hwpx) | 마크다운 |
|---|---|---|---|
| 그림 | 가운데 인라인 그림, 본문 폭 · 높이 80% 안에 맞춤(96dpi 기준, 키우지 않음), 그림 문단 줄간격 '한 줄', 다음과 함께 | BinData + 글자처럼 취급 그림, 가운데, 다음과 함께 | `![설명](fig:이름)` + 캡션 줄 |
| 그림 캡션 | 그림 아래 가운데 | 같음 | `**그림 1.** 설명` |
| 표 캡션 | 표 위 가운데, 다음과 함께 | 같음 | 표 위 줄 |
| 표 | Table Grid 테두리, 가운데, 머리글 줄 굵게 · 쪽마다 반복(tblHeader), 칸 정렬 | 본문 폭 표, 머리글 줄 반복(repeatHeader), 칸 여백 사용, 칸 정렬 | GFM 표 (`\|`는 `\\|`) |
| 목록 | 글머리 • ◦ ▪(단계별) · 번호, 내어쓰기 | 같음 | `- ` · `1. `, 하위는 부모 기호 폭만큼(`- ` 아래 2칸, `10. ` 아래 4칸) |

양식(학위논문 등)을 쓰면 캡션 · 그림 문단은 본문 글꼴 · 크기, 가운데, 들여쓰기 없음, 위(그림 · 표 캡션 앞) 또는 아래(그림 캡션)
6pt 이상. 표 칸은 본문 글꼴 · 크기, 줄간격 최대 130%, 앞뒤 간격 0. 쪽 나눔(`---`) 바로 뒤의 그림 · 표는 새 쪽에서 시작한다.
기본 (A4) 양식의 기존 블록 출력(골든 파일)은 바뀌지 않는다(글머리 기호는 depth 0이면 그대로 •).

다시 읽기: 내보낸 docx · hwpx는 인용 넣기(`compose.docx_scan/apply`, `hwpx_scan/apply`)와 양식 가져오기(`format_import`)가
그대로 읽는다(tests/test_writing_figures.py).

## 4. 편집기 (writing.js · writeedit.js · writetools.js)

도구 막대: `B I 장 절 • 글머리 1. 번호 ❝ 그림 표 | ＋ 인용 넣기 …` 오른쪽 끝 **?**(단축키 · 서식 도움말).

| 동작 | 단축키 / 방법 |
|---|---|
| 글머리 목록 켜기 · 끄기 (고른 줄 모두) | Ctrl+Shift+8 · [• 글머리] |
| 번호 목록 켜기 · 끄기 | Ctrl+Shift+7 · [1. 번호] |
| 다음 항목 (번호는 +1, 뒤 번호 다시 매김) | 목록 줄에서 Enter |
| 빈 항목에서 목록 끝 / 하위 항목이면 내어쓰기 | 빈 항목에서 Enter |
| 기호 지우기 / 하위 항목이면 내어쓰기 | 내용 맨 앞에서 Backspace |
| 들여쓰기 · 내어쓰기 (하위 항목도 함께) | Tab · Shift+Tab — 위 형제 항목의 내용 위치까지(번호 목록 3칸)라 마크다운에서 실제 하위 목록이 됨. 첫 항목은 하위가 될 수 없어 그대로 |
| 그림 넣기 | [그림](여러 장) · 붙여넣기 · 끌어 놓기 → `![그림 설명](fig:…)` 문단, '그림 설명'이 골라져 바로 고쳐 씀 |
| 표 넣기 · 고치기 | [표] · Ctrl+Alt+T — 커서가 표(또는 캡션 줄) 안이면 그 표를 고치는 창, 아니면 크기(줄 · 칸)를 고른 뒤 창 |
| 표 고치기 창 | 표 제목(캡션) · 참조 이름 · 칸 입력, 위/아래에 줄 추가 · 줄 삭제 · 왼쪽/오른쪽에 칸 추가 · 칸 삭제 · 칸 정렬, Enter = 아래 칸(마지막 줄이면 줄 추가), [표 삭제] |
| 미리보기에서 | 표를 누르면 표 고치기 창, 그림을 누르면 편집기에서 그 그림의 설명 글을 고름 |
| 도움말 | ? 버튼 · Ctrl+/ (모든 단축키와 쓰는 대로 바뀌는 서식) |

- 그림 · 새 표는 커서 자리에 문단으로 넣는다(앞뒤 빈 줄). 커서가 문장 가운데면 문장을 가르지 않고 그 줄 뒤에 넣는다.
- 표 고치기 창 · 미리보기 표 누르기는 `writeedit.findTables`로 표를 찾는다. 브라우저에서는 marked의 맨 바깥 표 토큰 위치를 그대로 써서
  미리보기의 n번째 표와 늘 같은 표를 고친다(앞 `|` 없는 GFM 표 포함, 구분선 칸 수가 다른 것 · 목록 안 표는 미리보기처럼 빠짐).
  marked가 없으면 같은 GFM 규칙의 줄 검사로 찾는다.
- 코드 블록(``` · ~~~) 안에서는 목록 Enter · Backspace · Tab 규칙을 쓰지 않는다(`writeedit.inFence`). Tab은 공백 2칸만.
- 모든 편집은 `execCommand("insertText")`로 한 번에 바꿔 **Ctrl+Z로 되돌릴 수 있다**(안 되는 브라우저는 setRangeText).
- 한글 조합 중(isComposing · keyCode 229)의 Enter · Backspace · Tab은 브라우저에 맡긴다.
- 번호 다시 매기기: 빈 줄 없이 이어진 덩어리 안에서 같은 단계 번호를 1씩. 덩어리 첫 번호(예: 3.)는 그대로, 하위 목록 첫
  항목 · 글머리 뒤에 새로 시작한 번호 목록은 1부터 — 마크다운 미리보기가 보여 주는 번호와 같게 맞춘다.
- AI 도우미 경로(runAi 등)는 건드리지 않았다.
