## 1. 목적

논문 쓰기 화면(`#/write/{id}`)에 **참고 패널**을 열어, 원고를 쓰면서 한 화면에서

- 서재 논문의 **PDF 원문**을 읽고(스크롤 · 하이라이트), 문장을 골라 **원고 커서 자리에 인용과 함께 넣고**,
- 내 **하이라이트 · 메모 · 노트**를 눌러 인용과 함께 넣고,
- 이미 만든 **AI 요약**과 **서지 정보**(제목 · 저자 · 초록 · 인용키)를 보고,
- 원고에 인용한 논문들의 인용 관계로 고른 **참고할 만한 논문(추천)** 을 보고 바로 서재에 넣거나 인용하게 합니다.

새로 만드는 것은 최소로 하고, 읽기 화면의 PDF 뷰어(`reader.js`) · 인용 그래프의 공용 캐시와 유사도 계산(`citegraph.py` · `graph_build.py`) · 서재 추가(`addPaper`)를 그대로 씁니다.

## 3. 범위

### 하는 것
1. **참고 패널**: 논문 쓰기 화면 오른쪽(좁으면 아래) 칸. 탭 **[PDF | 하이라이트·노트 | 요약 | 정보 | 추천]**, 머리줄의 **열린 논문 고르기**(최근 연 논문 목록) · 닫기(5 · 7장).
2. **여는 곳 세 군데**: 도구 막대 **[참고]** 버튼(단축키), 왼쪽 **"이 원고의 인용"** 의 논문, **`[@` 자동완성**에서 미리보기(5.1절).
3. **PDF 탭**: 읽기 화면의 PDF 뷰어를 패널 크기로 그대로 띄움(`reader.js` 임베드 모드 — 4.2절). 하이라이트 추가 · 수정 · 삭제, 선택 → **[인용으로 넣기]**(7.1절).
4. **원고에 넣기**: 선택 문장 · 하이라이트 · 메모 · 노트 선택 부분 · 인용키를 **원고 커서 자리**에 Pandoc 인용(`[@key, p. 12]`)과 함께 넣음. 형식은 8장.
5. **추천 탭 + 서버 계산**: 원고 인용 논문(OpenAlex 번호가 있는 것)을 씨앗으로, 1B 유사도를 **씨앗들에 걸쳐 합산**해 20편(9장). 새 엔드포인트 `POST /api/graph/recommend`(SSE — `/api/graph`의 진행 · 게이트 코드 재사용).
6. **저장**: 패널 열림 · 탭(브라우저 `localStorage`, 전역), 최근 연 논문(원고별 `localStorage`, 서재 논문 id만). **서버에 새로 저장하는 것 없음**(10장).
7. 자동 테스트(알고리즘 · API · 넣기 형식 순수 함수)와 수동 확인 목록(12 · 13장).

### 안 하는 것 (범위 밖)
- 패널에서 **AI 질문하기 · 요약 만들기**(읽기 화면에서. 패널은 이미 있는 요약만 보여 줌 — 사용자 결정 1 ③).
- 패널에서 **노트 고치기**(읽기 전용. 고치기는 읽기 화면 · 서재 상세의 노트 탭).
- **PDF 두 편 이상 동시에** 띄우기, 패널 **떼어 내기(새 창)**, 패널 폭 **끌어서 조절**(고정 비율 — 6장).
- 추천의 **그래프 그림 · 이전/이후 연구 목록**(인용 그래프 화면이 이미 있음), 원고 **본문 글**로 찾는 추천(임베딩 — 3단계), 추천 결과 **저장 · 기록 · 기기 간 동기화**.
- 추천 씨앗을 위한 **DOI → OpenAlex 번호 찾기 · Semantic Scholar 보강**(호출 예산 — K-6 · K-5).
- 서재 밖 논문의 **PDF 미리보기**(서재에 추가하면 볼 수 있음). 서재 논문 정보 탭의 인하대 · Google Scholar 링크(서재 상세에 있음 — 서재 밖 논문에는 둠, RD-2 · 7.4 · 7.5절).
- **[＋ 인용 넣기] 검색 창**에서 미리보기(자동완성 · 왼쪽 목록으로 충분).
- PDF 글자의 **줄 끝 하이픈 · 줄바꿈 복원**, OCR, **인쇄 쪽 번호 수동 보정 칸**(8.5절 — 넣은 뒤 글자로 고침).
- 최근 연 논문 목록의 **서버 저장 · 기기 간 이어 보기**(K-8).
- 읽기 상태 · "최근 연 논문"(서재) **바꾸기**(패널에서 연 것은 읽은 것으로 치지 않음 — K-10).

### 4.2 PDF를 패널에 띄울 수 있나 — 판단: **된다(임베드 모드, 기획팀 추천 K-1)**
코드를 본 결과, 렌더러 자체는 이미 **담는 칸의 크기에 맞춰** 동작합니다.
- `fitScale()`은 `R.scroller.clientWidth`(PDF 스크롤 칸 폭)로 배율을 정하고, `ResizeObserver`가 칸 폭이 바뀌면 다시 맞춤 → 패널 폭에 그대로 맞음.
- 쪽은 `IntersectionObserver`(`root: R.scroller`)로 보이는 것만 그림, 하이라이트 사각형은 **쪽 대비 비율(%)** 로 저장 · 표시, 선택 → 사각형 계산(`selectionRects`)도 쪽 요소 기준 → 칸 크기와 무관.
- 선택 도구 상자(`.sel-pop`)는 `document.body`에 고정 위치로 붙음 → 패널 안에서도 뜸.

| 3 | `openReader`의 부수 효과: `POST /api/papers/{id}/open`(읽기 상태 · 최근 연 논문), Esc → 서재로, 오른쪽 탭 | 새 export **`mountPdf(host, paper, opts)`** 는 이 셋을 하지 않음(K-10). 탭은 패널(`refpane.js`)이 가짐 |
| 4 | 선택 상자 · 하이라이트 상자의 **[AI에게 묻기]** 가 `showTab("chat")` | 임베드 모드에서는 숨기고, 선택 상자에 **[인용으로 넣기]** 추가(`opts.onQuote`가 있을 때) |
| 5 | 하이라이트를 만들거나 지우면 `R.tab === "highlights"`일 때만 목록 갱신 | 임베드 모드는 `R.tab`이 없어 그냥 넘어감. 패널은 **하이라이트·노트 탭을 열 때마다** `R.annotations`로 다시 그림 + 그 탭 안에서 지우거나 고치면 바로 다시 그림 |
| 6 | 다른 탭을 보는 동안 PDF 칸이 숨겨지면 `clientWidth = 0` → `ResizeObserver`가 배율을 최소(0.5)로 다시 맞춤 | `ResizeObserver` 콜백 맨 앞에 **폭 0이면 건너뜀** 한 줄 |
| 7 | PDF 첨부가 끝나면 `onRefresh`가 `hashchange`를 일으켜 화면을 다시 엶 → 쓰기 화면이 다시 열림 | 임베드 모드에서는 `hashchange` 대신 **패널 PDF만 다시 띄움** |
| 8 | 하이라이트 목록(`highlightsTab`) · 요약 그리기(`drawSummary`)가 모듈 안 함수 | **export** 하고 옵션만 더함: `highlightsTab(body, { onInsert })`(묻기 → 넣기), `drawSummary(body, s, { ask: false })`(물어보기 · 다시 만들기 버튼 없음) |

- 쓰는 API는 지금 것 그대로: `GET /api/papers/{id}` · `/pdf-url` · `/annotations` · `/summary`, `POST /api/papers/{id}/annotations`, `PATCH · DELETE /api/annotations/{id}`.
- **PDF 파일은 PDF 탭을 처음 볼 때 받음**(하이라이트·노트 · 요약 · 정보만 보면 받지 않음). `R`과 하이라이트 목록은 패널에서 논문을 열 때 만듦.
- 대안(채택 안 함): ① `reader.js`를 인스턴스(클래스)로 바꾸기 — 1,000줄 넘게 고쳐야 하고 지금 화면이 동시에 둘일 일이 없음 ② `#/read/{id}`를 `iframe`으로 — 앱 전체 · 로그인을 한 번 더 띄우고 원고 커서와 통신이 어려움 ③ PDF.js 기본 뷰어 — 하이라이트 · 넣기 없음.

## 5. 사용 흐름

```
[논문 쓰기 #/write/12]
  도구 막대 [참고] (Alt+R) ───────────┐
  왼쪽 "이 원고의 인용"의 논문 누르기 ──┤→ 참고 패널 (그 논문 · 마지막으로 본 탭)
  [@ 자동완성: Ctrl+Enter 또는 [보기] ─┘   (자동완성은 닫히지 않고 입력 초점도 원고에 그대로)
        ▼
  참고 패널
  ┌ 머리줄: [열린 논문 ▾ (최근 8편 · 다른 논문 찾기…)] [＋ 인용] [✕]
  ├ 탭: PDF | 하이라이트·노트 | 요약 | 정보 | 추천
  │   PDF: 문장 드래그 → [색 5개 | 인용으로 넣기 | 메모 | 복사] → 원고 커서 자리에 “…” [@key, p. 12]
  │   하이라이트·노트: 하이라이트마다 [넣기] [메모 넣기] [p.N], 노트(읽기 전용)에서 고른 부분 [선택한 부분 넣기]
  │   요약: 이미 만든 AI 요약(없으면 "읽기 화면에서 만들 수 있어요")
  │   정보: 제목 · 저자 · 학술지·연도 · DOI · 초록 · @인용키 [인용 넣기] [읽기 화면에서 열기]
  │   추천: 이 원고의 인용 N편으로 찾은 20편 → [인용 넣기] / [서재에 추가] [추가하고 인용] / 눌러서 정보 보기
  └
```

### 5.1 여는 곳
| 어디서 | 동작 | 초점 |
|---|---|---|
| 도구 막대 **[참고]** 버튼(`.writer-tools`의 [AI 도우미] 오른쪽) | 열림/닫힘 전환. 열 때 이 원고의 최근 목록 맨 위 논문을, 목록이 비면 **빈 상태**(아래) | 열면 고르기 상자, 닫으면 원고(RD-1) |
| **Alt+R** (RD-1) | 닫혀 있으면 **열기**. 열려 있고 초점이 패널 밖이면 **패널로 초점만**(닫지 않음). 초점이 패널 안이면 **닫기** | 열기 · 초점 이동은 고르기 상자, 닫으면 원고 |
| 왼쪽 **"이 원고의 인용"** 의 줄(서재에 있는 키만 버튼) | 패널을 열고 그 논문을 엶(이미 열려 있으면 논문만 바꿈) | 고르기 상자 |
| **`[@` 자동완성** — 고른 줄에서 **Ctrl+Enter**(macOS Cmd+Enter) 또는 줄 끝 **[보기]** | 패널을 열고 그 논문을 엶. **넣지 않고**, 자동완성 목록 · 원고 입력 초점은 그대로 | 원고(그대로) |
| 추천 탭 · 정보 탭 안의 논문 | 그 논문을 엶 | 고르기 상자 |

- **패널 제목**은 따로 두지 않고 머리줄의 **열린 논문 고르기 상자가 제목 겸 초점 자리**(RD-4 — 좁은 칸에서 같은 제목이 두 번 나오지 않게). 원고 칸에서는 Tab이 공백을 넣으므로 키보드로 패널에 가는 길은 Alt+R(RD-1).

- **빈 상태**: "원고에 인용한 논문이나 서재 논문을 골라 옆에 띄워 보세요." + **[서재에서 고르기]**(지금 `citePicker(ta, null, { multi: false, onPick })` 재사용 — 고른 논문을 엶) + 추천 탭은 그대로 쓸 수 있음.
- 서재에 없는 키(⚠ 줄)는 누를 수 없음(지금처럼 주황 표시).

### 5.2 여러 논문 사이 전환
- 머리줄 **열린 논문 고르기**: 기본 `<select>`(접근 가능한 이름 "열린 논문"). 항목 = 이 원고에서 최근 연 **서재 논문 최대 8편**(새로 연 것이 맨 위, 같은 논문은 위로 올림) + 맨 끝 "다른 논문 찾기…"(5.1절 [서재에서 고르기]와 같음).
- 추천에서 연 **서재 밖 논문**은 이 목록에 넣지 않음(메모리에만 — 다른 논문으로 바꾸면 사라짐. 서재에 추가하면 그때부터 목록에 들어감).
- 논문을 바꾸면 **같은 탭**을 유지(그 논문에 PDF가 없으면 PDF 탭은 "PDF가 없어요" 상태 — 7.1절).

### 5.3 닫기
[✕] · [참고] 버튼 · Alt+R(초점이 패널 안일 때). 닫으면 **초점은 원고 편집 칸**(편집 칸이 숨어 있으면 [참고] 버튼 — RD-1), `closeReader()`(PDF 메모리 풀기), 진행 중인 추천은 **계속**(결과는 메모리에 두고 다시 열면 보임 — 9.9절). 원고 화면을 떠나면(`closeWriter`) 추천도 멈춤.

## 6. 화면 배치 (격자)

지금 `.writer-body`는 `220px(왼쪽) | 편집 | 미리보기`, 1100px 이하 왼쪽 숨김, 760px 이하 위아래로 쌓기입니다(개발팀 최근 변경). 참고 패널은 **네 번째 칸**이고, 열려 있을 때 칸이 모자라면 **미리보기를 먼저 숨깁니다**(쓰면서 보는 것이 목적이라 편집 · 참고가 우선 — K-9).

| 화면 폭 | 패널 닫힘(지금 그대로) | 패널 열림 · 나란히 | 패널 열림 · 편집 | 패널 열림 · 미리보기 |
|---|---|---|---|---|
| **1501px 이상** | 왼쪽 · 편집 · 미리보기 | 왼쪽 · 편집 · 미리보기 · **참고** (세 칸 같은 폭) | 왼쪽 · 편집 · 참고 | 왼쪽 · 미리보기 · 참고 |
| **1101~1500px** | 같음 | 왼쪽 · 편집 · 참고 (**미리보기 숨김**) | 왼쪽 · 편집 · 참고 | 왼쪽 · 미리보기 · 참고 |
| **761~1100px** | 편집 · 미리보기 | 편집 · 참고 (미리보기 숨김) | 편집 · 참고 | 미리보기 · 참고 |
| **760px 이하** | 편집 위 · 미리보기 아래 | 편집 위 · **참고 아래** (미리보기 숨김, 위아래 반씩) | 같음 | 미리보기 위 · 참고 아래 |

- 칸 폭: 내용 칸은 모두 `minmax(0, 1fr)`(같은 폭). 1501px 이상 · 세 칸이면 칸마다 약 427~566px(1501~1920px) — PDF는 [맞춤]으로 칸 폭에 맞음.
- **미리보기가 숨은 동안** [나란히] 버튼에 설명(`title`): "참고 패널을 닫거나 화면을 넓히면 미리보기도 보여요". 숨겨도 미리보기 계산은 지금처럼 계속(왼쪽 "이 원고의 인용"이 그 결과를 씀).
- **미리보기 모드에서 넣기**: 편집 칸이 숨어 있어도 원고의 마지막 커서 자리에 들어가고(`textarea`는 숨어도 선택 위치를 기억), 미리보기가 바로 갱신됨 + 화면 읽기 알림과 **토스트** "원고에 넣었어요"(편집 칸이 보일 때는 토스트 없음 — 넣은 글이 바로 보이므로, RD-6).
- 패널 안: 머리줄 · 탭 줄은 고정, 아래가 스크롤(`.panel` · `.tabs` · `.panel-body` 재사용). PDF 탭은 작은 막대 + `.pdf-scroll`.
- 560px 이하: 지금 규칙(미리보기 여백 줄임) 그대로. 패널 머리줄의 고르기 상자는 줄어들고 탭 이름은 줄바꿈 없이 가로 스크롤(디자인).
- **CSS는 `app.css`의 지금 `.writer` 규칙(개발팀 최근 변경)이 들어간 뒤 그 위에** 더합니다(16장 순서). 새 단계 폭은 1500px 하나만 추가.

## 7. 탭별 동작

### 7.1 PDF
- 4.2절 임베드 모드. 막대: 쪽 `[n] / N`(Enter로 이동) · − · [맞춤] · ＋ · 하이라이트 색 5개. 처음 배율은 **맞춤**(패널 폭). 배율 · 색 선택은 읽기 화면과 같은 `paperlab.reader` 설정을 씀(따로 두지 않음).
- **문장을 드래그**하면 선택 상자: **[색 5개] · [인용으로 넣기] · [메모] · [복사]**. 색 · 메모는 읽기 화면과 같이 하이라이트를 만듦(서버에 저장 — 지금 API). [인용으로 넣기]는 하이라이트를 만들지 않고 **8.1절 형식으로 원고에 넣음**.
- 칠해진 하이라이트를 누르면 지금처럼 색 바꾸기 · 메모 · 복사 · 삭제(+ **[인용으로 넣기]**, [AI에게 묻기] 없음).
- **PDF가 없는 서재 논문**: 지금 `drawPdfMissing`(인하대에서 보기 · PDF 첨부) 그대로. 첨부가 끝나면 패널에서 PDF가 열림(4.2절 7번).
- **서재 밖 논문**(추천에서 연 것): PDF · 하이라이트·노트 · 요약 탭은 **꺼짐**(`aria-disabled="true"`), 누르면 "서재에 추가하면 볼 수 있어요" + [서재에 추가].

### 7.2 하이라이트·노트
- 위: 하이라이트 목록 — 지금 읽기 화면 `highlightsTab` 재사용(쪽 순서 · 색 필터 · 메모 수정 · 삭제 · `.md`). 항목마다 **[넣기]**(8.2절), 메모가 있으면 **[메모 넣기]**(8.3절), **p.N**(PDF 탭으로 가서 그 쪽 — PDF를 아직 안 받았으면 받은 뒤 이동). [묻기] 없음.
- 아래: **노트**(`GET /api/papers/{id}`의 `note`) — **읽기 전용 `textarea`**(키보드로 커서 이동 · 선택 가능), 아래 **[선택한 부분 넣기]**(선택이 없으면 꺼짐, 설명 "노트에서 넣을 부분을 고르세요") → 8.3절. 노트가 비면 "노트가 없어요. 읽기 화면에서 쓸 수 있어요."
- 하이라이트가 없으면 지금 문구 그대로("PDF에서 문장을 드래그하면 …").

### 7.3 요약
- `GET /api/papers/{id}/summary` → 있으면 지금 `drawSummary` 그대로(한 줄 요약 · 질문/방법/결과 · 수준별 설명 · 섹션별 정리 · 핵심 수식 · 기여 · 한계 · 생각해 볼 질문). **[물어보기] · [다시 만들기] 없음**. 섹션의 **p.N**은 PDF 탭으로 가서 그 쪽.
- 없으면: "아직 AI 요약이 없어요. 읽기 화면에서 만들 수 있어요." + [읽기 화면에서 열기](`#/read/{id}` — 원고는 지금처럼 떠날 때 저장). 이동 전에 `paperlab.reader`의 `tab`을 `"summary"`로 저장해 읽기 화면이 **요약 탭으로** 열리게 함(그곳의 [요약 만들기]를 사용자가 누름 — 패널에서 AI를 부르지 않음, RD-3).
- 넣기 버튼 없음(사용자 결정 1 ③ "보여 줌". AI가 쓴 글을 인용문처럼 넣지 않게).

### 7.4 정보
- 서재 논문: 제목, 저자(앞 8명 + "외 N명" — `authorsShort`), 학술지 · 연도(`issued`), DOI(링크 — 새 탭), **초록**(6줄 접기 — 1B 시안 `.abstract.clamp` 재사용), **`@인용키`** + **[인용 넣기]**(8.4절) + **[읽기 화면에서 열기]**. 인용 정보가 빈 경우 지금 `issuesBox` 경고(채우기 버튼 포함) 재사용.
- 서재 밖 논문(추천): 같은 칸을 추천 응답의 `paper`로(인용키 없음) + **[＋ 서재에 추가]** · **[PDF 포함 추가]**(`pdf_url`이 있을 때) · **[추가하고 인용]**(9장 끝 — K-12) + **글자 링크 [인하대에서 보기] · [Google Scholar]**(RD-2 — 1A 규칙 그대로: `paperProxyTarget(paper)`가 있을 때만 인하대, `bindExtLink`로 처음 안내 창, Scholar 질의 = 제목 없으면 DOI, 새 탭 `noopener noreferrer`) + "추천 이유"(9.6절 문구). 맨 위 **[← 추천 목록]**. 서재 논문 정보 탭에는 이 두 링크를 두지 않음(서재 상세에 있음).

## 8. 원고에 넣는 형식

모든 넣기는 지금 `insertText(ta, text)`로 **원고 커서 자리(선택이 있으면 그 자리를 바꿈)** 에 넣고 저장 · 미리보기가 지금처럼 갱신됩니다. 넣은 뒤 입력 초점은 원고로 돌아가고 커서는 넣은 글 뒤(지금 `insertText` 동작), 화면 읽기 알림 "원고에 넣었어요"(편집 칸이 숨어 있으면 토스트도 — RD-6).
형식 함수는 DOM 없는 순수 모듈 **`static/js/refquote.js`**(새 파일 — Node로 시험, 12.D절)에 둡니다.

### 8.1 PDF에서 고른 문장 — 직접 인용 (팀장 결정 K-3 · **사용자 결정 U-1: APA 방식 + 둥근 따옴표 “ ”**, 2026-10-08)
- 모양은 **APA 방식 + 둥근 따옴표 “ ” 한 가지**(개정 2026-10-08 — 팀장 전달: 개발팀이 `QUOTE_STYLE`의 모양 분기(`mode` · `quotes` — 다른 모양으로 바꾸는 길)를 없애 단순화). 설정 창 없음(RD-5). 따옴표 글자 · 40단어 기준은 `refquote.js` **한 곳에서만** 정하고, 화면 설명 문구(시안 10.1절)도 그 값을 씀.
- **짧은 인용(40단어 미만)**: 본문 안 인용 — `“{문장}” [@{key}, p. {쪽}]`
- **긴 인용(40단어 이상)**: 인용 블록 — 새 문단으로 `> {문장} [@{key}, p. {쪽}]`(따옴표 없음. APA 7판 "40단어 이상은 블록 인용" 규칙)
- 단어 수 = 공백으로 나눈 조각 수(지금 상태 줄의 단어 수와 같은 셈 — 한국어는 어절).
- 쪽: 선택이 한 쪽 안이면 `p. 12`, 두 쪽 이상에 걸치면 첫 쪽–끝 쪽 `pp. 12–13`(지금 `parseCitation`이 둘 다 쪽 번호로 읽음). 쪽 번호 규칙은 8.5절.
- 문장은 지금 읽기 화면처럼 공백 · 줄바꿈을 한 칸으로 합친 것(`sel.toString().replace(/\s+/g, " ").trim()`).

### 8.2 하이라이트 [넣기]
8.1절과 같은 규칙(하이라이트의 `text` · `page`). 쪽은 그 하이라이트의 쪽 하나.

### 8.3 메모 · 노트 — 간접 인용(내 말)
- 하이라이트 **[메모 넣기]**: `{메모} [@{key}, p. {쪽}]` — 따옴표 없음(내 글이므로).
- 노트 **[선택한 부분 넣기]**: `{고른 글} [@{key}]` — 쪽 없음, 따옴표 없음. 노트는 원래 마크다운이라 **이스케이프하지 않음**, 여러 줄이면 줄바꿈을 그대로 둠.

### 8.4 인용키만
정보 탭 · 머리줄 [＋ 인용] · 추천 [인용 넣기]: `[@{key}]`(지금 `citePicker`가 넣는 모양과 같음).

### 8.5 쪽 번호 (기획팀 추천 K-2)
뷰어의 쪽(`R.pages` · 하이라이트 `page`)은 **PDF 파일의 몇 번째 쪽**이고, 인용에 필요한 것은 **논문에 인쇄된 쪽**입니다.
1. 서재 논문의 `pages`가 `첫쪽-끝쪽`(숫자 두 개, 하이픈 · en dash)이고 **`끝 − 첫 + 1 = page_count`**(PDF 쪽 수 — PDF를 올릴 때 저장됨)이면 → 인쇄 쪽 = `첫쪽 + (PDF 쪽 − 1)`.
2. 그 밖(쪽 정보 없음 · 수가 안 맞음 · 로마 숫자 · `e1234` 같은 논문 번호)은 → **PDF 쪽 그대로** 넣고, 그 논문에서 처음 넣을 때 한 번 알림: "인쇄된 쪽 번호를 알 수 없어 PDF 쪽({n})으로 넣었어요. 필요하면 원고에서 고쳐 주세요."
3. 패널 PDF 막대 끝에 작은 글씨로 기준을 보임: "인용 쪽: 인쇄 쪽(345–360)" 또는 "인용 쪽: PDF 쪽".

### 8.6 이스케이프 · 띄어쓰기
- PDF 문장 · 하이라이트 글(8.1 · 8.2절)은 마크다운 특수 문자 **`\` `*` `_` `` ` `` `[` `]` `<`** 앞에 `\`를 붙임(PDF 글의 `[12]` · `p < .05*` 같은 것이 굵게 · 링크 · HTML로 바뀌지 않게). 메모 · 노트(8.3절)는 그대로.
- **본문 안 넣기**(8.1 짧은 인용 · 8.3 · 8.4): 커서 앞 글자가 공백 · 줄바꿈 · `(` · 문서 처음이 아니면 앞에 공백 한 칸.
- **블록 넣기**(8.1 긴 인용): 앞이 문서 처음이 아니면 빈 줄 하나로 문단을 나누고(`\n\n` — 이미 있으면 더 넣지 않음), 뒤에 `\n\n`.

## 9. 추천 (서버)

### 9.1 씨앗 (기획팀 추천 K-6)
- 화면이 보냄: **원고에 인용한 서재 논문의 id**(미리보기 계산 결과 `W.built`의 인용 묶음 순서 = 원고에 **처음 나온 순서**, 중복 제거, 최대 **200개**). 인용키 → 논문 id는 화면이 이미 가진 서재 목록(`W.papers`)으로 바꿈. 서재에 없는 키는 보내지 않음.
- 서버: **사용자 권한(`user_tx`, RLS)** 으로 그 논문들을 읽고, `openalex_id`가 1B 형식(`^W[1-9][0-9]{0,11}$`)에 맞는 것만 씨앗으로. 내 서재에 없는 id(남의 논문 포함)는 **조용히 뺌**(있는지 알리지 않음). 앞에서부터 **최대 20편**(`REC_MAX_SEEDS`, 가정 — 넘으면 경고 `seeds_capped`).
- DOI만 있는 논문의 OpenAlex 번호 찾기 · Semantic Scholar 참고문헌 보강은 하지 않음(호출 예산 — 화면 안내 7.5절).

### 9.2 후보 모으기 · 호출 예산 (기획팀 추천 K-5)
- 씨앗마다 그래프의 **A · B · C 단계 그대로**(`GraphBuilder.gather(seed)` — `build()`에서 떼어 낸 것): 씨앗 서지(단건 조회 — 무료), 참고문헌 앞 300편 + 관련 논문 20편의 서지 · 참고문헌 목록(묶음 조회), 씨앗을 인용한 논문 피인용 순 100편. **캐시가 유효하면 외부 호출 0회**(1B와 같은 TTL). 추천에서는 S2 보강을 하지 않음(9.1절).
- **C 목록 캐시 (Q-1 팀장 결정)**: 씨앗의 `cited_by_top`(1B — C · D 완료 표시) 또는 **`cited_by_top_c`**(C만 끝남)가 유효하면 C는 캐시. 둘 다 아니면 C를 받아 **`cited_by_top_c`에 씀**(추천은 D를 외부에서 받지 않으므로 `cited_by_top`을 쓰면 그래프가 D를 건너뛰게 됨). 그래프도 C를 새로 받으면 같은 행을 씀(사용자 결정 I-1 "흔적 구분 못 하게" — 9.8절 6번). 유효 기간 30일 · 상한 100(1B 7.6 · 8.3절). 같은 씨앗으로 나중에 그래프를 만들면 이 목록을 C로 다시 쓰고 **D만 받은 뒤** `cited_by_top`을 씀. 정식 이름 + 마이그레이션 `20261008000003_citation_edges_top_c.sql`(검사 제약만 교체), 쓰지 않는 `cited_by_recent`를 이 뜻으로 재사용하지 않음.
- D 단계(함께 인용)는 **캐시만 읽음**(외부 호출 없음 — 구현 반영 ①): 대상 = **씨앗 + 씨앗마다 예비 유사도 상위 49편**(`citegraph.prelim_targets(ix, seed=씨앗)` — 1B 6.5절 D 대상과 같은 규칙, 0점 제외, 중복 제거). `store.citers(대상, today, COCITE_PER_SORT = 100)`(피인용 순 100 ∪ 최신순 100). 그래서 씨앗이 하나면 그 씨앗 그래프와 같은 풀이 됨. E 단계 대신 **결과 20편 가운데 초록이 없는 것만** 묶음 조회 1회(`REC_ABSTRACT_CALLS = 1`).
- 예산: 추천 1회 **OpenAlex 목록 호출 최대 12회**(`GraphSources(max_list_calls=12)` — 초록 1회 포함, 그래프 1회와 같은 값), 전체 **45초** 기한, 그래프와 같은 서버 전체 속도 제한(초당 10회).
- 씨앗은 원고 순서대로 처리. **예산 · 기한이 다 되면** 남은 씨앗 가운데 **캐시에 있는 것만** 쓰고(외부 호출 없이), 못 쓴 씨앗 수를 돌려줌(`seeds_used < seeds_total`, 경고 `partial`). 받은 것은 그 자리에서 캐시에 쓰므로 **[다시 계산]하면 이어서** 반영됨.
- 대략: 참고문헌 100편 이하인 처음 보는 씨앗 1편 ≈ 목록 2회 → 한 번에 처음 보는 씨앗 약 5편. 이미 그래프를 본 씨앗 · 다른 사용자가 본 씨앗은 0회.

### 9.3 점수 (`citegraph.recommend(ix, seeds, n)` — 입출력 없는 순수 함수)
```
풀 = Pool(첫 씨앗) 에 모든 씨앗 · 씨앗별 A · B · C · 캐시 D를 넣음 (1B 중복 합치기 그대로)
S  = { pool.canon(s) : 씨앗 s }          ← 제목 합치기로 씨앗 번호가 바뀌어도 같은 노드
후보 w ∈ 풀 − S
sim_s(w)  = similarity(ix, s, w).weight   ← 1B 6.4절 그대로(인용 근거 없을 때만 related 폴백)
total(w)  = Σ_{s∈S} sim_s(w)
rank(w)   = W_RANK_SIM · total(w) + ln(1 + cited_by_count(w))   ← 1B 6.5절 식, sim 자리에 합계
linked(w) = |{ s : sim_s(w) > 0 }|
kind(w)   = Σ 성분(0.6·coupling, 0.4·cocitation, related 부분) 가운데 가장 큰 것
seeds(w)  = sim_s(w)가 큰 씨앗 최대 3개 (같으면 번호 오름차순)
```
- `total(w) = 0`이면 빼고, `rank` 내림차순(같으면 번호 오름차순) **20편**(`REC_N`, 가정). 제목 빈 작품은 풀에 없음(1B 규칙).
- 계산량: 씨앗 20 × 후보(최대 약 8,600 = 20 × 420 + 캐시 D 200) ≈ 17만 쌍. **2초 기준은 서버 계산 경로 전체**(품질팀 I-3): `cg.index` 1회(A · B · C 풀) → 씨앗 20편마다 `prelim_targets`(D 대상 — 9.2절) → 캐시 D를 더한 뒤 `cg.index` 1회 더 → `cg.recommend`. 캐시 읽기 · 초록 받기 등 DB · 외부 입출력은 빼고 셈. **실측 1.37초**(2026-10-08 — 팀장 전달, AC-R05). 넘으면 개발팀이 팀장에게 보고(대안: 씨앗당 참고문헌 상한을 150으로).
- 수치는 1B 상수(`W_COUPLING` · `W_COCITATION` · `MIN_SHARED` · `W_RELATED` · `W_RANK_SIM`)를 그대로 쓰고, 새 상수는 `REC_MAX_SEEDS = 20` · `REC_N = 20` · `REC_ABSTRACT_CALLS = 1`만(`citegraph.py` 맨 위 한 곳).

### 9.4 API (기획팀 추천 K-4)
**`POST /api/graph/recommend`** → `text/event-stream`
```json
{"paper_ids": [12, 34, 56]}
```
- 본문 최대 4KB(`/api/graph`와 같은 읽기 방식). `paper_ids`: 양의 정수(int64 범위) 1~200개, 중복은 하나로. 그 밖 키는 무시.
- 인증 · `X-PaperLab: 1` · Origin 규칙은 1단계 그대로.
- 스트림 시작 전 오류(일반 JSON):

| 상태 | `code` | 경우 · 문구 |
|---|---|---|
| 400 | `bad_request` | 본문 형식 위반 · 4KB 초과 · 개수 밖 — "추천 요청이 올바르지 않아요." |
| 400 | `no_seeds` | 내 서재에서 OpenAlex 번호가 있는 논문이 0편 — "인용한 논문에 OpenAlex 번호가 없어 찾을 수 없어요." |
| 429 | `graph_busy` | 이 사용자의 그래프 · 추천이 이미 진행 중(**`GraphGate`를 그래프와 함께 씀** — 사용자당 1개) |
| 503 | `graph_queue_full` | 서버 전체 진행 2 · 대기 4가 다 참(그래프와 같은 게이트) |

- 구현: 지금 `graph_events`를 **"만드는 일 · 사용자별 마무리" 두 함수를 받는 생성기**로 일반화해 그래프와 추천이 함께 씀(대기 · `wait` 이벤트 · 15초 `: ping` · 끊김 감지 · 게이트 반납 · 완료 로그). 같은 씨앗 합치기(`Flights`)는 키 `("rec", 정렬한 씨앗 번호들)`로 그대로 씀(메모리에만, 끝나면 지움).
- 기존 `POST /api/graph`는 바꾸지 않음.

### 9.5 SSE 이벤트
```
{"type":"progress","step":"wait","message":"다른 그래프가 끝나기를 기다리는 중","progress":0.05}
{"type":"progress","step":"seeds","message":"인용 논문 정보를 모으는 중 (3/12)","progress":0.3}
{"type":"progress","step":"finish","message":"초록 받는 중","progress":0.85}
{"type":"progress","step":"compute","message":"추천 계산","progress":0.95}
{"type":"done","recommend":{…9.6절…}}

```
- 캐시로 다 되면 `progress` 없이 바로 `done`일 수 있음. 클라이언트가 끊으면 남은 외부 호출을 멈추고 받은 것은 캐시에 남음(1B 9.2절과 같음).

### 9.6 `done.recommend` 모양
```json
{
  "items": [{
    "id": "W1234567890",
    "rank": 7.912, "score": 0.8123, "linked": 3, "kind": "coupling",
    "seeds": ["W111", "W222", "W333"],
    "paper": {"title": "…", "authors": […], "author_count": 8, "year": 2019, "venue": "…", "doi": "…",
              "openalex_id": "W1234567890", "url": "…", "pdf_url": "…", "cited_by_count": 512, "abstract": "…", …},
    "in_library": 77
  }],
  "seeds_total": 14, "seeds_used": 9,
  "warnings": [{"code": "partial", "message": "…"}],
  "stats": {"candidates": 3120, "list_calls": 7, "cache_hits": 3010, "elapsed_ms": 8200, "built_on": "2026-10-08"}
}
```
- `paper`는 1B `paper_view`와 같은 키 → 화면이 `addPaper(paper)`를 그대로 씀. `abstract`는 1,500자까지.
- `score` = `total`(소수 4자리), `seeds` = 씨앗 OpenAlex 번호(요청한 사용자가 보낸 자기 서재 논문의 번호 — 화면이 `W.papers`로 인용키에 맞춰 "@vaswani2017attention 외 2편과 연결"처럼 보일 수 있음. 서버가 논문 id로 바꾸지 않으므로 합치기 경로에서도 남의 id가 섞이지 않음).
- `in_library`: 요청한 사용자 서재의 논문 id 또는 null(1B와 같은 `match_library`, 사용자 트랜잭션 — 합치기 경로에서도 사용자마다 따로).
- `seeds_total` = 9.1절로 고른 씨앗 수(최대 20), `seeds_used` = 그중 참고문헌 또는 인용 논문 정보가 있어 계산에 들어간 수.
- 경고 code: 1B 목록 재사용 — `partial`(예산 · 기한, 문구는 화면이 7.5절 "한 번에 다 보지 못해 …"로), `refs_partial`, `citing_failed`, `abstracts_failed`, `stale_cache`, `upstream_limited`, `weak_citation_data`(결과의 `kind`가 절반 넘게 `related`) + **신규 `seeds_capped`** "인용이 많아 처음 나온 20편만 바탕으로 했어요." 모르는 code면 서버 `message`(1B GD-4 규칙).
- **`upstream_limited` 문구 (구현 반영 ⑦)**: 서버는 추천용 문구를 따로 두지 않고 **1B와 같은 문구**를 보냄(`graph_build.py` `ERRORS` · `WARNINGS` — 경고는 "…저장돼 있던 정보로만 그렸어요…"). 화면은 아는 code는 **code별 자기 문구**를 씀: 경고 "OpenAlex 하루 사용량을 다 써서 저장돼 있던 정보로만 찾았어요(한국 시간 오전 9시에 초기화). 설정에서 OpenAlex API 키를 넣으면 한도가 10배가 돼요." + [설정 열기], 오류는 7.5절 표. 다른 경고(`refs_partial` · `citing_failed` · `abstracts_failed` · `stale_cache`)도 화면 문구로 "일부 정보 없이 찾았어요" 상자에 모음. 서버 `message`는 화면이 모르는 code일 때만 보임.
- 응답에 공용 캐시 내부 id · 다른 사용자 정보 · 원시 오류 문구 없음.

### 9.7 동시성 · 부하
- `GraphGate`를 그래프와 함께 씀: 서버 전체 동시 2 · 대기 4, **사용자당 1개**(그래프와 추천을 합쳐서). 스레드에서 계산(이벤트 루프를 막지 않음 — 1B와 같음).
- DB: 씨앗 · 후보 캐시 읽기는 묶음 질의(`store.works` · `store.edges`)로, 외부 호출 동안 연결 반납. 쓰기는 단계마다 짧은 `system_tx("citation cache write")`.

### 9.9 다시 계산하는 시점 (기획팀 추천 K-7)
- 화면은 원고별로 마지막 결과와 그때 씨앗 목록(정렬한 논문 id 문자열)을 메모리에 둠.
- **자동**: 추천 탭을 열었을 때 결과가 없거나 **씨앗 목록이 달라졌으면** 계산.
- **탭을 보는 동안 원고 인용이 바뀌면**: 보이는 결과가 **있으면** 자동으로 다시 하지 않고 알림 "원고의 인용이 바뀌었어요. [다시 계산]"(타이핑마다 서버를 부르지 않게). 결과가 **아직 없으면**(인용 없음 · 번호 없음 화면) 탭 내용을 다시 판단해, OpenAlex 번호가 있는 씨앗이 생기면 **자동 계산**(구현 반영 ④ — 예: 인용이 없던 원고에 첫 인용을 넣는 순간). 오류 · 취소로 결과가 없는 경우는 씨앗 목록이 그때와 달라졌을 때만 자동 계산.
- **[다시 계산]**: 언제든(같은 씨앗이어도 — 예산에 걸려 못 쓴 씨앗을 이어서 반영).
- 계산 중 원고를 떠나면(`closeWriter`) · 로그아웃하면 멈춤(`AbortController`). 패널을 닫거나 다른 탭으로 가도 계속.
- **이전 결과 유지 (구현 반영 ③)**: 다시 계산이 [취소] · 실패 · 원고 떠남으로 끝나면 이전 결과가 있을 때 그 목록을 그대로 둠(7.5절 "취소" 줄). 로그아웃 때는 모두 비움(10장).

## 14. 위험

- **PDF 두 번 받기 · 메모리**: 패널에서 논문을 바꿀 때마다 PDF를 새로 받음(서명 주소가 매번 달라 브라우저 캐시가 잘 안 됨). 큰 PDF(100MB)는 느림. 한 번에 한 편만 메모리에 둠(바꾸면 `doc.destroy()`). 자주 오가는 것이 문제면 최근 1편 캐시를 팀장에게 제안.
- **전역 `R` 재사용**: 나중에 읽기 화면과 쓰기 화면을 함께 띄우는 기능이 생기면 `reader.js`를 인스턴스로 바꿔야 함(그때 범위 — K-1).
- **쪽 번호**: 8.5절 규칙이 맞지 않는 PDF(표지 · 부록이 붙은 PDF인데 `pages`와 쪽 수가 우연히 같음)는 틀린 인쇄 쪽이 들어갈 수 있음. 패널 막대에 기준을 보이고, 넣은 글은 사용자가 고칠 수 있음.
- **PDF 글자 품질**: 줄 끝 하이픈 · 합자 · 2단 조판에서 선택 순서가 섞일 수 있음(읽기 화면 복사와 같은 품질). 이스케이프 뒤에도 인용문 안에 `@`가 든 `[…]`가 있으면 인용 표시로 읽힐 수 있음(드묾 — 원고에서 주황 표시로 드러남).
- **추천 품질**: 1B와 같은 한계(OpenAlex 인용 정보 · 국문 논문 · 수백 편 범위). 씨앗이 적으면(1~2편) 그래프 한 장과 비슷한 결과. 실측(M-R07) 뒤 수치 조정.
- **예산**: 처음 보는 인용이 많은 원고는 여러 번 [다시 계산]해야 다 반영됨. 서버 PC 하루 OpenAlex 예산을 그래프 · 검색과 나눠 씀(1B M-9와 같은 수용 위험).
- **사용자당 1개 게이트**: 다른 탭에서 그래프를 만드는 동안 추천이 429 — 문구로 안내.
- **"원고에 인용됐다"가 공용 캐시에 남는 문제 (품질팀 I-1 — 해결, 사용자 결정 2026-10-08 "흔적 구분 못 하게")**: `cited_by_top_c`를 추천만 쓰면 그 행이 "이 작품이 누군가의 원고에 인용됐다" + 날짜를 드러내고, 사용자가 3~5명뿐이라 관리자(`paperlab` 스키마는 Data API에 노출되지 않아 관리자만 봄)는 누구인지 짐작하기 쉬웠음. → **그래프도 C를 새로 받으면 `cited_by_top_c`를 씀**(개발팀 변경 중). 남는 것은 1B와 같은 "누군가 이 주변을 봤다" 수준(수용 — 9.8절 5 · 6번, 1B 13장).
- **남는 신호 — 행 조합 (수용 위험, 팀장 결정 2026-10-08)**: "`cited_by_top_c`만 있고 `cited_by_top`은 없음"은 "추천이 쓰였거나, 그래프가 D 전에 끊겼다"는 뜻으로 읽힐 수 있음. 약한 신호이고 관리자만 봄. 완전히 막으려면 추천도 D를 받아야 하는데 씨앗마다 외부 호출이 2회 늘어 추천 예산(목록 12회 — 9.2절)이 맞지 않아 막지 않음. 이 신호는 그 씨앗으로 그래프를 만들면(`cited_by_top`이 생김) 없어짐. 30일이 지나면 캐시로는 쓰이지 않지만 **행 자체는 남음**(용량 정리 `cache-prune` 때 지워지거나 다시 받을 때 덮어씀 — 1B 8.5절). 사용자에게는 팀장이 마무리 보고에서 알림.
- **격자**: 1101~1500px에서 패널을 열면 미리보기가 숨음 — 처음에는 "미리보기가 사라졌다"로 느낄 수 있음([나란히] 설명 · M-R08).
