## 1. 목적

워드·한글의 논문 양식(용지, 여백, 글꼴, 글자 크기, 줄간격, 문단 모양, 표지)을 **미리 저장해 두고**, 원고를 워드(.docx)·한글(.hwpx)로 내보낼 때 **고른 양식대로** 만들어 줍니다.

- **확정**: 학교 양식 + 일반 프리셋을 함께 제공합니다.
- **확정**: 양식을 만드는 방법은 두 가지 — **양식 파일(.docx · .dotx · .hwpx)을 올려 서식 읽어오기**, **화면에서 항목별로 수정하기**.
- **확정**: 사용자 3~5명이 석사논문·박사논문·대체 보고서를 제각각 쓰므로 **세 경우를 똑같이** 제공합니다.
- 학교: **인하대학교 제조혁신전문대학원**. 안내문 3개(학위청구 논문 작성 안내 · 표지/속표지/인정서 예시 · 석사학위논문 대체 보고서 안내)의 값을 그대로 씁니다.

## 2. 범위

### 하는 것
1. 양식 데이터 구조와 기본 제공 양식 4개(읽기 전용)
2. 내 양식: 기본 양식 복사해서 만들기 · 이름 바꾸기 · 항목별 수정 · 삭제
3. 양식 파일 가져오기(.docx · .dotx · .hwpx → 서식 추출 → 확인·수정 → 저장)
4. 원고마다 양식 선택(저장) + **표지 정보** 입력
5. 내보내기: 고른 양식으로 docx · hwpx 생성, 표지 → 속표지 → 인정서(인준서), 쪽 번호
6. 편집 화면 미리보기에 양식 일부 반영(11.5절)

### 안 하는 것
[14장 범위 밖](#14-범위-밖) 참고. 대표: **목차 자동 생성**, 영문 속표지, 책등, 표지 배치 화면 편집, PDF 내보내기.

## 4. 양식 데이터 구조

### 4.1 단위와 공통 타입

| 타입 | 형태 | 설명 |
|---|---|---|
| `Length` | `{"value": 3, "unit": "ch"}`, `{"value": 12.7, "unit": "mm"}`, `{"value": 40, "unit": "pt"}` | `ch` = **글자 수**. 1ch = 그 문단의 글자 크기(pt). 예: 11pt 본문에서 3ch = 33pt = 11.64mm. `pt` = 포인트(1pt = 25.4/72mm). 예: 한글 기본 탭 40pt ≈ 14.1mm |
| `Fonts` | `{"hangul": "휴먼명조", "latin": "휴먼명조", "hanja": "휴먼명조"}` | 한글 · 영문 · 한자 글꼴 이름. **글꼴 이름은 규정에 적힌 그대로** 저장·출력(확정). 안내문의 "신명조"·"신명 세명조"는 **"한양신명조"**로 씀(확정, Q12) |
| `Align` | `"left" \| "center" \| "right" \| "justify"` | `justify` = 양쪽 정렬(안내문의 "혼합") |
| `TextStyle` | 아래 표 | 제목 · 제목 수준 · 인용문 · 각주 · 참고문헌이 함께 쓰는 글자·문단 모양 |

`TextStyle` 필드 (없는 필드는 괄호 안 기본값):

| 필드 | 타입 · 범위 | 뜻 |
|---|---|---|
| `fonts` | `Fonts \| null` (null) | null이면 양식의 `fonts`를 씀 |
| `size_pt` | 5~72 | 글자 크기 |
| `bold` · `italic` | bool (false) | 굵게 · 기울임 |
| `align` | `Align` (`left`) | 정렬 |
| `line_spacing_pct` | 50~500 \| null (null) | 줄간격 %. null이면 본문 값 |
| `space_before_pt` · `space_after_pt` | 0~200 (0) | 문단 위 · 아래 간격 |
| `indent_left` · `indent_right` | `Length` (0mm) | 왼쪽 · 오른쪽 들여쓰기 |
| `first_line_indent` | `Length` (0mm) | 첫 줄 들여쓰기(음수 = 내어쓰기) |
| `page_break_before` | bool (false) | 새 쪽에서 시작 |

### 4.2 양식(preset) 전체 구조

예시는 기본 양식 ③ "인하대 제조혁신전문대학원 학위논문"입니다. 저장 형식은 JSON, `schema`는 구조 버전입니다.

```json
{
  "schema": 1,
  "page": {
    "width_mm": 188, "height_mm": 257,
    "margin_mm": {"top": 15, "bottom": 21, "left": 24, "right": 21},
    "header_mm": 5, "footer_mm": 8, "gutter_mm": 0
  },
  "fonts": {"hangul": "휴먼명조", "latin": "휴먼명조", "hanja": "휴먼명조"},
  "body": {
    "size_pt": 11, "line_spacing_pct": 180, "align": "justify",
    "first_line_indent": {"value": 3, "unit": "ch"},
    "space_before_pt": 0, "space_after_pt": 0
  },
  "title": {"show": false, "size_pt": 16, "bold": true, "align": "center", "space_after_pt": 12},
  "headings": {
    "1": {"size_pt": 16, "bold": true, "align": "center", "space_after_pt": 12, "page_break_before": true},
    "2": {"size_pt": 13, "bold": true, "align": "left", "space_before_pt": 12, "space_after_pt": 6},
    "3": {"size_pt": 11, "bold": true, "align": "left", "space_before_pt": 6}
  },
  "quote": {"size_pt": 11, "line_spacing_pct": 160, "align": "justify", "indent_left": {"value": 40, "unit": "pt"}},
  "footnote": {"size_pt": 10, "line_spacing_pct": 140},
  "bibliography": {
    "size_pt": 11, "line_spacing_pct": 180, "align": "justify",
    "hanging_indent": {"value": 10, "unit": "mm"}, "new_page": true
  },
  "page_number": {"show": true, "position": "footer-center", "start": "first_chapter", "dashes": false, "distance_mm": null},
  "cover": {"kind": "thesis", "fonts": {"hangul": "HY신명조", "latin": "HY신명조", "hanja": "HY신명조"}, "bold": true}
}
```

| 키 | 설명 |
|---|---|
| `page` | 용지 폭·높이(mm, 50~500), 여백(mm, 0~100). **여백은 한글(편집 용지)의 뜻으로 저장**합니다: 본문은 `위쪽 + 머리말` 아래에서 시작하고 `아래쪽 + 꼬리말` 위에서 끝납니다. 워드 변환은 4.3절. `gutter_mm`(제본)는 0 고정(범위 밖) |
| `fonts` | 양식 전체 기본 글꼴 |
| `body` | 본문 문단(`paragraph`). 목록·표 행·코드 블록도 본문 글꼴·크기·줄간격을 따르되 들여쓰기는 지금 규칙(목록 8+6×깊이 mm, 내어쓰기 5mm) 유지, 코드 블록은 지금처럼 Consolas 9.5pt |
| `title` | 논문 제목(`#`). `show: false`면 **본문에 넣지 않고** 표지의 국문 제목 기본값으로만 씀 |
| `headings."1"~"3"` | 장(`##`) · 절(`###`) · 항(`####` 이하) |
| `quote` | 인용문(`>`) |
| `footnote` | 각주 내용(크기 · 줄간격만 씀) |
| `bibliography` | 참고문헌 항목(`bib_entry`). `hanging_indent` = 내어쓰기 폭(번호식 스타일처럼 블록의 `hanging`이 false면 내어쓰기 안 함). `new_page` = 참고문헌 제목을 새 쪽에서 시작. 참고문헌 제목(`bib_heading`)은 `headings."1"` 모양을 쓰되 새 쪽 여부는 `new_page`를 따름 |
| `page_number` | `show`; `position`: `footer-center` · `footer-right` · `header-center` · `header-right`; `start`: `document`(본문 첫 쪽부터 1) · `first_chapter`(첫 `##` 장부터 1, 그 앞 원고 부분은 쪽 번호 없음); `dashes`: 번호 양옆 줄표(`- 1 -`); `distance_mm`: null이면 꼬리말(머리말) 영역 안 기본 위치, 숫자(0~100)면 **용지 아래(위) 끝에서 쪽 번호 줄까지의 거리** — 학과 확인 결과(Q3·Q4)에 맞춰 양식 설정에서 바꿀 수 있게 둔 값. 글자 크기·글꼴은 본문과 같음. **표지류에는 항상 쪽 번호가 없고 쪽 수에도 세지 않음** |
| `cover` | `kind`: `none` · `thesis`(학위논문 표지 세트) · `report`(대체 보고서 표지 세트), `fonts`(null이면 양식 글꼴), `bold`. 표지 배치(줄 위치·크기)는 `kind`별로 코드에 고정(6장) — 화면에서 배치를 고치는 것은 범위 밖 |

검증: 범위를 벗어나거나 형식이 틀리면 400과 **어느 항목인지** 알려 줍니다(예: `body.size_pt: 5~72 사이로 입력해 주세요`). 빠진 항목은 그 양식의 `base`(복사해 온 기본 양식) 값으로 채웁니다.

### 4.3 워드·한글 변환 규칙

| 항목 | 한글(.hwpx) | 워드(.docx) |
|---|---|---|
| 용지 | `pagePr width/height` = mm × 7200 / 25.4 (HWPUNIT) | 구역 `page_width/height` |
| 위 여백 | `margin top` = 위쪽, `header` = 머리말 | **위 여백 = 위쪽 + 머리말**, **머리글 거리 = 위쪽** (본문 영역이 한글과 같아지도록 — 팀장 결정으로 확정, Q2) |
| 아래 여백 | `bottom` = 아래쪽, `footer` = 꼬리말 | **아래 여백 = 아래쪽 + 꼬리말**, **바닥글 거리 = 아래쪽** |
| 좌우 여백 | `left` · `right` | 그대로 |
| 글꼴 | `charPr fontRef`의 `hangul` · `latin` · `hanja`가 각각 해당 이름의 `fontface`를 가리킴 | `rFonts eastAsia` = 한글 글꼴, `ascii`·`hAnsi` = 영문 글꼴. 워드는 한자 글꼴을 따로 지정할 수 없어 한글 글꼴을 씀 |
| 줄간격 % | `lineSpacing type="PERCENT" value=%` | **고정값 = 글자 크기 × % ÷ 100 (pt)** (확정, Q1): `lineRule="exact"`, `line` = 크기 × % ÷ 100 × 20 (twip). 예: 11pt × 180% = 19.8pt → `line=396`. 한글과 쪽 수가 비슷해짐. 그 문단의 글자 크기 기준(제목은 제목 크기, 각주는 각주 크기) |
| 첫 줄 들여쓰기 `ch` | `intent` = 글자 수 × 글자 크기(pt) × 100 (HWPUNIT). 예: 3ch × 11pt = 3300 | `firstLineChars` = 글자 수 × 100 **그리고** `firstLine` = 글자 수 × 글자 크기 × 20 (twip). 예: 300 / 660 |
| `mm` 길이 | mm × 7200 / 25.4 | mm × 1440 / 25.4 (twip) |
| `pt` 길이 | pt × 100 | pt × 20 (twip). 예: 40pt → 한글 4000, 워드 800 |
| 정렬 | `JUSTIFY` · `LEFT` · `CENTER` · `RIGHT` | `both` · `left` · `center` · `right` |
| 문단 위/아래 | pt × 100 (HWPUNIT) | pt × 20 (twip) |
| 쪽 번호 | 쪽 번호 매기기(`pageNum`, 위치) + 본문 시작 구역에서 1로 다시 시작 | 머리글/바닥글에 `PAGE` 필드 + 구역 `pgNumType start="1"` |
| 쪽 번호 `distance_mm` | 꼬리말(머리말)로 쪽 번호를 넣고 그 위치가 용지 끝에서 지정 거리가 되게 배치(구현 방법은 개발팀. 한글 실렌더링으로 확인됨 — 13장 K) | 바닥글(머리글) 거리 = `distance_mm`. 본문 위·아래 여백은 그대로 |

### 5.1 ① 기본 (A4) — 지금 결과 그대로

- 이 양식(또는 양식을 지정하지 않은 요청)으로 내보내면 **지금 `to_docx` · `to_hwpx` 코드 경로를 그대로** 씁니다. docx · hwpx 결과가 바뀌지 않아야 합니다(수용 기준 AC-01~03).

### 6.2 배치 규칙 (모든 표지류 공통)

- 표지류는 각자 **한 쪽**이며 쪽 번호·머리말·꼬리말이 없고, 쪽 수에 세지 않습니다(본문이 1쪽부터).
- 모든 줄은 **가운데 정렬**, 첫 줄 들여쓰기 없음, 표지 글꼴(`cover.fonts`)·굵게(`cover.bold`).
- **줄 높이 = 글자 크기 × 1.2** 로 고정합니다(docx: 고정 줄간격 `exact` = 크기 × 1.2pt, hwpx: 줄간격 120%). 위치를 계산할 수 있게 하기 위함입니다.
- 표의 "위 N" = 용지 **위 끝**에서 첫 줄 윗부분까지, "간격 N" = 앞 줄 아래에서 이 줄 위까지, "아래 N" = 마지막 줄 아래에서 용지 **아래 끝**까지(아래 묶음을 이 위치에 맞춤), **"채움"** = 남는 높이를 채움 칸끼리 똑같이 나눔.
- 제목처럼 길어서 여러 줄이 되는 경우 줄 수만큼 높이를 잡습니다. 줄 수는 추정합니다: 한글·한자·전각 = 글자 크기 × 1.0, 영문·숫자·기호 = × 0.55, 공백 = × 0.3을 더해 사용 폭(용지 폭 − 좌우 여백 × 2)으로 나눠 올림.
- 남는 높이가 모자라면 채움을 0으로 하고 내보내기 응답에 경고를 붙입니다(10.4절, 화면 토스트 "표지 내용이 한 쪽을 넘을 수 있어요").
- 모든 간격이 고정인 쪽(인준서 등)은 위에서부터 차례로 놓고, "아래 N"은 참고값입니다(검사하지 않음).
- 구현 방법(구역 분리, 문단 앞 간격 등)은 개발팀이 정하되 결과 위치는 위 규칙을 따릅니다.

## 7. 내보내기 동작

1. 화면이 지금처럼 블록을 만들고 `doc_format`(양식 id)과 `cover`(표지 정보)를 함께 보냅니다(10.4절).
2. 서버는 양식을 찾아(없으면 400) 적용합니다. `doc_format`이 없거나 `default`이면 **지금 코드 경로 그대로**.
3. 문서 순서: [표지 → 속표지 → 인정서/인준서 (`cover.kind ≠ none`이고 `include`가 켜진 것만)] → [원고 본문] .
4. **구역 나누기**:
   - 표지류 구역: 쪽 번호·머리말·꼬리말 없음.
   - `page_number.start = first_chapter`: 첫 `##` 장 앞의 원고 부분(국문초록 등)은 쪽 번호 없는 구역, 첫 `##`부터 새 구역에서 **1쪽**. 원고에 `##`가 없으면 본문 처음부터 1쪽.
   - `page_number.start = document`: 본문 첫 쪽부터 1쪽(표지류는 세지 않음).
   - 구역 시작 문단은 새 쪽에서 시작합니다.
5. 블록별 적용: `title` → `title`(show가 false면 건너뜀), `heading` → `headings."1"~"3"`, `paragraph` · `list_item` · 표 행 → `body`, `quote` → `quote`, `bib_heading` → `headings."1"` + `bibliography.new_page`, `bib_entry` → `bibliography`, 각주 내용 → `footnote`, `page_break` → 쪽 나눔(지금과 같음).
6. 굵게·기울임·위/아래 첨자·각주 런 처리는 지금과 같습니다.
7. **마크다운(.md) 내보내기는 양식과 무관**합니다(같은 원고면 양식을 바꿔도 결과가 같음).
8. **목차 자동 생성은 범위 밖**입니다. 대체 보고서 순서(인준서 → 목차 → 본문)를 지키려면 사용자가 워드·한글의 차례 기능으로 넣도록 내보내기 완료 토스트/도움말에 안내합니다: "목차는 워드(참조 → 목차) · 한글(도구 → 차례/색인)로 넣어 주세요."
9. 워드·한글 문서에 인용 넣기(`/api/compose/*`)는 **원래 서식을 유지하는 기능이므로 양식을 적용하지 않습니다**.

## 8. 양식 파일 가져오기

- 받는 파일: **.docx · .dotx · .hwpx**, 20MB 이하. .doc · .hwp · .dot 등은 400 "워드는 .docx나 .dotx로, 한글은 .hwpx로 저장해서 올려 주세요".
- 결과는 **저장하지 않은 양식**으로 돌려주고, 사용자가 확인·수정한 뒤 저장합니다(만들기 API).
- 못 읽은 항목은 `base`(기본 `default`) 값으로 채우고 `missing`에 적습니다. 반올림: mm 0.1, pt 0.5, % 정수.
- 표지·쪽 번호·인용문·참고문헌 모양은 읽지 않습니다(`base` 값 유지). 단, 아래 표에서 읽는다고 적은 것은 예외.

| 항목 | .docx / .dotx | .hwpx |
|---|---|---|
| 용지·여백 | **마지막 구역**(문서 끝 `sectPr`)의 용지·여백. 한글 뜻으로 역변환: 위쪽 = 머리글 거리, 머리말 = 위 여백 − 머리글 거리(음수면 위쪽 = 위 여백, 머리말 = 0). 아래도 같음 | 첫 구역 `pagePr`(HWPUNIT → mm) 그대로 |
| 본문 | `Normal` 스타일(+ `docDefaults`): `rFonts eastAsia` → 한글·한자 글꼴, `ascii` → 영문 글꼴(테마 글꼴만 있으면 `theme1.xml`에서 찾고, 없으면 missing), `sz` → 크기, `spacing line` → %(`exact`: line ÷ 20 ÷ 크기 × 100 — 4.3의 역변환, `atLeast`도 같은 계산 + 경고, `auto`(배수): line ÷ 240 × 100 근사 + 경고), `ind firstLineChars` → ch, `firstLine` → mm(크기의 정수배면 ch), `jc` → 정렬, 위/아래 간격 | `바탕글`(engName `Normal`) 스타일의 `paraPr`(정렬, `lineSpacing PERCENT`; 다른 종류면 근사 + 경고, `intent` → 크기의 정수배면 ch 아니면 mm, 위/아래) · `charPr`(`height` ÷ 100 → pt, `fontRef` hangul/latin/hanja → 글꼴 이름) |
| 제목 1~3 | 스타일 이름 `heading 1~3`(한국어 워드도 내부 이름은 영문), `basedOn` 따라가서 실제 값 | `개요 1~3`(engName `Outline 1~3`) |
| 논문 제목 | `Title` | (없음 → missing) |
| 인용문 | `Quote` | (없음) |
| 각주 | `footnote text` | `각주`(engName `Footnote`)가 있으면 |
| 참고문헌 | `Bibliography` | (없음) |

- .dotx는 python-docx가 바로 열지 못하므로 메모리에서 `[Content_Types].xml`의 문서 형식을 `document.main+xml`로 바꿔서 엽니다.
- 학과 양식 파일에 흔한 사용자 정의 스타일(예: "장제목")은 읽지 않습니다(범위 밖) — 화면에서 고치도록 안내합니다.

## 9. 저장 (DB)

나중에 Postgres로 옮기므로(1단계) **DB 테이블**에 저장합니다.

```sql
CREATE TABLE IF NOT EXISTS doc_formats (
    id         INTEGER PRIMARY KEY,
    name       TEXT NOT NULL,
    base       TEXT NOT NULL DEFAULT 'default',   -- 복사해 온 기본 양식 id
    data       TEXT NOT NULL DEFAULT '{}',        -- 4.2의 JSON
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);
```

- 기본 양식 4개는 DB에 넣지 않고 코드(`paperlab/doc_formats.py`)에 둡니다.
- 사용자 양식의 API id는 `user-{id}` 입니다(예: `user-3`).
- `manuscripts`에 열 2개 추가(`db.py`의 `MIGRATIONS`로 기존 서재에 덧붙임): `doc_format TEXT NOT NULL DEFAULT 'default'`, `cover TEXT NOT NULL DEFAULT '{}'`(6.1의 JSON).
- 설정(`settings.json`)에 `doc_format_default`(새 원고의 기본 양식, 기본값 `"default"`) 추가.
- 사용자 양식은 최대 50개. 이름은 1~60자.
- 1단계 이관 때 `user_id` 열과 `jsonb`로 바뀝니다.

## 10. API 계약

모든 쓰기 요청(POST · PATCH · PUT · DELETE)은 지금 규칙대로 **`X-PaperLab: 1` 헤더**가 있어야 합니다(없으면 403). 오류는 지금처럼 `{"detail": "한국어 메시지"}`.

### 10.1 양식

**목록** `GET /api/doc-formats`
```json
[
  {"id": "default", "name": "기본 (A4)", "builtin": true, "base": null, "cover_kind": "none",
   "description": "지금까지의 내보내기 서식 (A4, 바탕/Times New Roman 11pt)", "updated_at": null},
  {"id": "inha-mie-thesis", "name": "인하대 제조혁신전문대학원 학위논문 (석사·박사)", "builtin": true, "base": null,
   "cover_kind": "thesis", "description": "188×257mm, 휴먼명조 11pt, 줄간격 180%", "updated_at": null},
  {"id": "user-3", "name": "내 학위논문 (12pt)", "builtin": false, "base": "inha-mie-thesis",
   "cover_kind": "thesis", "description": "", "updated_at": "2026-10-06T05:12:44+00:00"}
]
```
순서: 기본 양식 4개(5장 순서) → 내 양식(수정 최신순).

**조회** `GET /api/doc-formats/{id}` → 위 항목 + `"data": { …4.2… }`, `"created_at"`. 없으면 404 "양식을 찾을 수 없어요".

**만들기** `POST /api/doc-formats`
```json
{"base": "inha-mie-thesis", "name": "내 학위논문 (12pt)"}
```
또는(가져오기 결과 저장)
```json
{"base": "default", "name": "학과 양식", "data": { …4.2… }}
```
→ 200, 조회와 같은 모양. `data`가 없으면 `base` 양식 값을 그대로 복사. `base`가 기본 양식 id가 아니면 400.

**수정** `PATCH /api/doc-formats/{id}`
```json
{"name": "새 이름", "data": { …4.2 전체… }}
```
둘 다 선택. `data`는 **통째로 바꿈**(빠진 항목은 `base` 값으로 채움). 기본 양식이면 **403** "기본 양식은 바꿀 수 없어요. 복사해서 내 양식으로 만들어 쓰세요". 응답: 조회와 같은 모양.

**삭제** `DELETE /api/doc-formats/{id}`
```json
{"ok": true, "reset_manuscripts": 2}
```
그 양식을 쓰던 원고는 `default`로 돌아가고, `doc_format_default`가 그 양식이면 `default`로 바꿉니다. 기본 양식이면 403.

**가져오기** `POST /api/doc-formats/import` (multipart: `file`, 선택 `base`)
```json
{
  "source": {"kind": "docx", "filename": "학위논문양식.dotx"},
  "suggested_name": "학위논문양식",
  "base": "default",
  "data": { …4.2… },
  "found": ["page.width_mm", "page.height_mm", "page.margin_mm.top", "page.header_mm", "fonts.hangul",
            "fonts.latin", "body.size_pt", "body.line_spacing_pct", "body.first_line_indent", "body.align",
            "headings.1.size_pt", "headings.1.bold"],
  "missing": ["title", "quote", "footnote", "bibliography", "headings.3"],
  "warnings": ["Normal 스타일 줄간격이 '배수'라 %로 바꿔 근사했어요"]
}
```
**저장하지 않습니다.**

### 10.2 원고

- `GET /api/manuscripts/{id}` 응답에 `"doc_format": "inha-mie-thesis"`, `"cover": { …6.1… }`(객체) 추가. 지워진 양식을 가리키면 `default`로 돌려줍니다.
- `GET /api/manuscripts` 목록 항목에 `doc_format` 추가.
- `POST /api/manuscripts`: 선택 `doc_format`. 없으면 설정의 `doc_format_default`.
- `PATCH /api/manuscripts/{id}` (기존 확장): 
  ```json
  {"doc_format": "inha-mie-thesis"}
  {"cover": { …6.1 전체… }}
  ```
  `doc_format`이 없는 양식이면 400 "양식을 찾을 수 없어요". `cover`는 통째로 바꾸며, 형식 오류(예: `graduation: "2027-13"`, `advisors` 3명, `committee` 6명)는 400. 응답은 지금처럼 `{"ok": true, "updated_at": …}`.

### 10.3 설정

`GET/PUT /api/settings`에 `doc_format_default` 추가. 없는 양식 id면 400.

### 10.4 내보내기 `POST /api/export-document` (기존 확장)

```json
{
  "format": "docx",
  "blocks": [ … ],
  "meta": {"title": "스마트 제조 공정의 품질 예측 연구"},
  "filename": "스마트 제조 공정의 품질 예측 연구",
  "doc_format": "inha-mie-thesis",
  "cover": { …6.1… }
}
```
- `doc_format` 없음 또는 `"default"` → 지금 경로. 없는 id → 400. `format: "md"`면 둘 다 무시.
- `cover`가 없으면 빈 표지 정보로 간주(빈 칸은 ○ 표시). `cover_kind = none`인 양식이면 무시.
- 응답은 지금과 같은 파일. 경고가 있으면 헤더 `X-PaperLab-Warnings`에 URL 인코딩한 JSON 배열(예: `["cover-overflow:front"]`, `["cover-missing:name,department"]`). 화면은 이것을 토스트로 보여 줍니다.

### 11.1 원고 편집 화면 상단 막대

`← 원고 | 제목 | 저장됨 | [인용 스타일 ▾] [양식 ▾] [표지 정보] [내보내기 ▾]`

- **양식 선택**: 묶음 "기본 양식"(4개) · "내 양식"(n개), 맨 아래 "양식 관리…"(관리 대화상자 열기). 바꾸면 바로 `PATCH doc_format` 저장, 미리보기 다시 그림. 툴팁 "내보낼 때 쓸 논문 양식".
- **표지 정보** 버튼: 고른 양식의 `cover_kind`가 `none`이 아닐 때만 보입니다. 필수 항목(이름 · 학과 · 졸업 연월)이 비어 있으면 버튼에 점 표시.

### 11.4 설정 창 · 양식 관리 대화상자

- **설정 창**(`settingsDialog`): "인용" 구역 다음에 **"논문 양식"** 구역 — "새 원고 기본 양식" 선택 + [양식 관리…] 버튼 + 도움말 "원고마다 편집 화면 위쪽에서 바꿀 수 있어요."
- **양식 관리 대화상자**(넓은 창, 제목 "논문 양식"):
  - 왼쪽 목록: "기본 양식"(배지 "기본") · "내 양식". 위에 [＋ 새 양식](어떤 양식을 복사할지 고르는 메뉴) · [양식 파일 가져오기].
  - 오른쪽: 고른 양식의 항목. **기본 양식**은 모든 칸 읽기 전용 + [복사해서 내 양식 만들기], 근거 설명(5장의 안내문 문구·가정 표시). **내 양식**은 수정 가능 + [이름 바꾸기] [삭제](확인 창: "'{이름}' 양식을 지울까요? 이 양식을 쓰는 원고 n개는 기본 (A4)로 바뀌어요.") [저장]. 저장 안 한 변경이 있으면 다른 양식을 고를 때 확인.
  - 항목 묶음: ① 용지·여백(용지 선택 A4 / 4×6배판 188×257 / Letter / 직접 입력, 위쪽·머리말·아래쪽·꼬리말·왼쪽·오른쪽 mm — 도움말 "한글 '편집 용지'와 같은 뜻이에요. 워드에서는 위 여백 = 위쪽 + 머리말로 바뀌어 들어가요.") ② 글꼴(한글·영문·한자, 입력 + 추천 목록: 휴먼명조, HY신명조, 한양신명조, 바탕, 함초롬바탕, Times New Roman, 맑은 고딕) ③ 본문 ④ 논문 제목(본문에 넣기) ⑤ 제목 1~3수준(장 · 절 · 항) ⑥ 인용문 ⑦ 각주 ⑧ 참고문헌 ⑨ 쪽 번호(넣기, 위치, 시작: "본문 첫 쪽부터" / "첫 장(##)부터 1쪽", 줄표, 용지 끝에서 거리 mm — 비우면 꼬리말 영역 기본 위치) ⑩ 표지(없음 / 학위논문 / 대체 보고서, 표지 글꼴, 굵게).
  - **글꼴 도움말**(글꼴 묶음에 항상 표시, 확정):
    > 휴먼명조·HY신명조는 한컴오피스와 함께 설치되는 글꼴이고, 한양신명조(안내문의 신명조·신명 세명조)는 한글 프로그램 안에만 있는 글꼴이에요. 워드 파일에도 규정 글꼴 이름을 그대로 넣기 때문에, 이 글꼴이 없는 PC의 워드에서 열면 비슷한 다른 글꼴로 보여요. 제출할 파일은 한컴오피스가 설치된 PC에서 확인하세요.
  - **가져오기 흐름**: 파일 고르기(끌어다 놓기 가능) → 읽는 중 표시 → 오른쪽 폼에 "가져온 양식 (저장 전)" 상태로 채움. 파일에서 읽은 칸에는 "파일에서 읽음", 못 읽은 칸에는 "기본값" 표시, 경고 목록 표시. 이름 칸 기본값 = 파일 이름. [저장] → `POST /api/doc-formats`, [취소] → 버림.

### 11.5 미리보기 반영 범위 (결정)

편집 화면 오른쪽 미리보기(`.doc`, 지금 최대 폭 760px)에 **아래만** 반영합니다.

| 반영함 | 방법 |
|---|---|
| 용지 폭 대비 여백 비율 | 미리보기 종이 폭 = 용지 폭, 안쪽 여백 = (위쪽 + 머리말) · 오른쪽 · (아래쪽 + 꼬리말) · 왼쪽을 같은 비율로 |
| 글꼴 | `font-family` = 양식 한글 글꼴, 영문 글꼴, 그다음 지금 대체 목록("바탕", "Batang", "Noto Serif KR", serif) — PC에 없으면 브라우저가 대체 |
| 글자 크기 | pt를 종이 폭 비율로 환산한 px |
| 줄간격 | `line-height` = % ÷ 100 (한글의 % 뜻과 같음) |
| 첫 줄 들여쓰기 · 정렬 | 본문 · 인용문 · 참고문헌 내어쓰기 |
| 제목 · 제목 1~3수준 | 크기 · 굵게 · 기울임 · 정렬, `title.show=false`면 제목을 흐리게 + "표지에만 들어가요" 표시 |
| 새 쪽 시작 | 해당 제목 위에 지금의 "쪽 나눔" 점선 표시 |

반영하지 않음: 실제 쪽 나눔·쪽 번호·머리말/꼬리말, 표지류(표지 정보 대화상자의 문구 미리보기로 대신), 각주 위치(지금처럼 끝에 모아 표시), 용지 높이.
**기본 (A4) 양식에서는 미리보기가 지금과 똑같이** 보여야 합니다(변수를 설정하지 않음).

화면 코드(개발팀)와 CSS(디자인팀)가 맞물리도록 미리보기 변수 이름을 고정합니다. 개발팀이 `.doc` 요소에 인라인으로 설정하고 디자인팀이 CSS에서 씁니다:
`--doc-paper-w`, `--doc-pad-t`, `--doc-pad-r`, `--doc-pad-b`, `--doc-pad-l`, `--doc-font`, `--doc-size`, `--doc-lh`, `--doc-indent`, `--doc-align`,
`--doc-title-size`, `--doc-title-align`, `--doc-title-weight`, `--doc-h{1,2,3}-size`, `--doc-h{1,2,3}-align`, `--doc-h{1,2,3}-weight`, `--doc-h{1,2,3}-style`,
`--doc-quote-size`, `--doc-quote-lh`, `--doc-quote-indent`, `--doc-fn-size`, `--doc-bib-size`, `--doc-bib-lh`, `--doc-bib-hang`. 양식이 적용된 상태는 `.doc.doc-formatted` 클래스로 구분합니다.

## 13. 수용 기준

품질팀이 실행해서 확인합니다. 특별한 말이 없으면 **자동 검사**(pytest + python-docx / zip XML 읽기)로 확인할 수 있게 쓴 것입니다. 허용 오차: 길이 ±0.1mm(docx twip · hwpx HWPUNIT 반올림), 표지 위치 ±1mm.

**공통 입력**: `tests/test_writing.py`의 `BLOCKS`에 `##` 장 두 개(첫 장 앞에 본문 문단 하나), `###` 절, `####` 항, 인용문, 참고문헌을 더한 블록 목록. 표지 정보: `degree=master, degree_field=공학, title_en="A Study", graduation=2027-02, department=스마트제조공학과, name=김인하, spaced_name=true, advisors=[홍길동], committee=["","",""]`, 원고 제목 "스마트 제조 연구".

### A. 기본 (A4) 호환
- **AC-01** `doc_format` 없이 docx를 내보내면 `word/document.xml` · `word/styles.xml` · `word/footnotes.xml`이 **변경 전 코드로 만든 골든 파일**과 바이트 단위로 같다. (골든 파일은 개발팀이 `writer.py`를 고치기 **전에** 만들어 `tests/golden/`에 둔다)
- **AC-02** `doc_format` 없이 hwpx를 내보내면 `Contents/header.xml`이 골든 파일과 같고, `Contents/section0.xml`은 무작위 값 속성(`hp:p`의 `id`, `instId`)을 지운 뒤 골든 파일과 같다.
- **AC-03** `doc_format: "default"`를 지정해도 AC-01 · AC-02와 같다. 마크다운 내보내기는 어떤 양식을 지정해도 결과가 같다.
- **AC-04** 기존 테스트가 모두 통과한다(0단계 당시에는 Windows의 알려진 실패 `test_cli_engine_with_fake_claude` 1건 제외 — 2026-10-07 해결, 이제 제외 없음).
- **AC-05** 기본 (A4) 양식을 고른 원고의 미리보기 `.doc` 요소에 `doc-formatted` 클래스와 `--doc-*` 변수가 없다(화면이 지금과 같음, 수동 확인 가능).

### B. 양식 API
- **AC-06** `GET /api/doc-formats`가 `default`, `apa7-student`, `inha-mie-thesis`, `inha-mie-report` 4개를 이 순서로 `builtin: true`로 돌려준다.
- **AC-07** `POST /api/doc-formats {"base":"inha-mie-thesis","name":"내 학위논문"}` → `id`가 `user-`로 시작, `builtin: false`, `data`가 기본 양식 `data`와 같다. 다시 목록을 받으면 들어 있다.
- **AC-08** 내 양식에 `PATCH`로 `data.body.size_pt = 12`를 보내면 조회 결과가 12이고 `updated_at`이 바뀐다. `name`만 보내면 이름만 바뀐다.

- 장·절 번호 자동 매기기(원고에 쓴 대로 나감), 머리말 문구(장 제목 등), 홀짝 쪽 다른 머리말, 제본 여백
- 4·5수준 제목(APA Level 4·5의 문단 안 제목)
- 양식 파일의 사용자 정의 스타일(예: "장제목")·표 서식·각주 번호 모양 읽기, .doc · .hwp · .dot 가져오기
- PDF 내보내기
- 미리보기의 실제 쪽 나눔·쪽 번호·표지 배치 재현
- 워드·한글 문서에 인용 넣기(compose)에 양식 적용
- 사용자끼리 양식 공유(서재는 각자 — 확정)
- 분량(30쪽 이상)·장 순서 검사
